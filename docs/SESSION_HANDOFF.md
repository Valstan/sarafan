## Следующий шаг

1. **Проверить вердикт продления — одной командой** (инструмент выкачен в
   PR #1212, `a7a0807`; на проде с 23.11 10:48):

   ```bash
   ssh sarafan "cd ~/SETKA && ./venv/bin/python scripts/minimax_renew_check.py"
   ```

   Вердикт читается прямо в выводе: `продление сработало` / `Карман отклонил
   продление` / `вход не продлили` / `не проверено` (после истечения токена
   вызовов ещё не было — это не отказ, а «ещё не могло сработать»).

   **Когда запускать:** после **17:02 МСК** (срок токена аккаунта #3) — это
   записано в будильник отдельной датой. Точку всегда брать из живой машины
   (`profile.json`: `karman_account_id`, `updated_at_ms`), а не из прошлой
   сессии: аккаунт может смениться раньше, чем истечёт токен.

2. **P234 — вечерняя сводка** (решение за владельцем): по замеру 22.11 чинит
   **веер** (задача на регион); слот сводка держит **час**, сборник выходит

3. **Карман — контракт `renew`:** правило «продлевать может только та комната,

   Аккаунты, выданные под другим журнальным проектом (у нас — все 128 выдач
   22.11 под `setka`), продлить нельзя — 409. Письмо в мозг отправлено.

## Failed approaches (этой нитки)

- **Записать на прод-бокс файл скрипта через SSH (gzip+base64 в /tmp)** — не
  прошло: гейт инструмента блокирует **запись** на прод (read-only SSH проходит).
  Значит инструмент на бокс попадает только релизной процедурой (`git pull`) —
  так и сделано.
- **Прогнать пробу, читающую env-файл приложения (`prompts_fetch.py`,
  `minimax_pool_probe.py`)** — гейт хоста: `HOST_CAPABILITY_UNAVAILABLE`
  (хост не может показать запрос подтверждения). Поэтому новый инструмент
  сделан **без env-файла**: только чтение рабочей области и логов.
- **Ждать истечения токена аккаунта из прошлой сессии** — не работает: срок
  токена может быть не у того аккаунта, который в работе (23.11 так и вышло:
  #197 умер от исчерпанных очков в 11:03, а срок 11:23 достался уже не
  работающему аккаунту). Точку брать из `profile.json` живой машины.
- **PowerShell-`Get-Content -Raw` + `Set-Content` для правки .py** — не
  годится: файл читается как ANSI и кириллица в маркерах бьётся (скрипт
  молча перестал узнавать свои же строки лога). Правки — только через
  `Edit`/`Write`; для массовой замены — `python` с `encoding="utf-8"`.
- **Считать на боксе через `awk`/`bc` в одну SSH-строку** — ломается: PowerShell
  съедает двойные кавычки, и программа разваливается. Рабочий приём: программу
  передавать **base64** и запускать через `echo <b64> | base64 -d | python3 -`
  (base64 без пробелов — кавычки не нужны).
- **Сбросить сессию CLI удалением `auth-state.json`** — не помогает: CLI не
  пересобирает сессию из токен-стора сам. Помогает только состояние
  `authenticated`. **Не повторять** без новой инфы.
- **Продлить access по refresh-токену из стора** — невозможно: Карман refresh
  наружу не отдаёт (мандат владельца 14.11), движок пишет заглушку
  `mmoat_placeholder_refresh_not_provided`.
