## Failed approaches (этой нитки)

- **Проксировать в приложение «всё подряд» (catch-all `location /`).** На стенде
  гейт выключен (`WEB_AUTH_ENABLED=0`), и приложение отдаёт операторский
  интерфейс без сессии — дашборд, `/tokens`, `/ad`, ключи. Такой конфиг
  опубликовал бы **весь САРАФАН** в интернет, и выглядел бы «просто
  работающей страницей». **Правило:** публичная граница живёт в транспорте —
  белый список точных путей. Закреплено тестом
  `tests/test_infra/test_nginx_valentin_public.py`.
- **`$proxy_add_x_forwarded_for` для IP посетителя.** Дописывает адрес edge'а, а
  приложение берёт **первый** элемент `X-Forwarded-For` — первым оказывается
  edge, и все посетители публичного домена склеиваются в одного клиента (лимит
  100/мин на всех). **Правило:** передавать заголовок edge'а как есть.
- **`sub_filter` с одиночным обратным слэшем (`href\":\"/\"`).** Парсер nginx
  съедает `\` при чтении строки в кавычках, и паттерн искал `href":"/"` (без
  слешей) — то есть ничего. **Правило:** в конфиге удваивать слеши.
- **Вложенный `location` внутрь блока с `alias`.** Ассеты `/portfolio/_next/static/`
  отдавались 404. **Правило:** выносить такой блок наверх (более длинный префикс
  и так побеждает).
- **Redis как служба Windows.** Служба идёт под LocalSystem, а на каталог с
  бинарниками доступ есть только у владельца (ACL: `PC79\valstan`) → «Access is
  denied». **Правило:** либо выдавать SYSTEM права на папку, либо оставить
  процесс под владельцем — выбрано второе (задача + S4U).
- **Запуск `redis-server.exe` напрямую в задаче.** Сборка msys2 форкается:
  родитель выходит, задача теряет управление и перезапускается раз в минуту,
  новый redis падает с «Address already in use». **Правило:** запуск через
  `RedisService.exe run --foreground`.
- **`$unit.NoLogin` / `$unit.NoEnv` без `ContainsKey`.** На юните без такого
  ключа хеша обращение под StrictMode бросает исключение, и переменная
  сохраняет значение **предыдущей** итерации — юнит тихо наследовал чужой
  триггер (и все юниты стали S4U). **Правило:** флаги из хеша читать через
  `ContainsKey`.
- **Остановка задачи как остановка юнита.** `Stop-ScheduledTask` снимает
  верхушку цепочки, а супервизор (powershell) выживает и продолжает поднимать
  экземпляры — за один рестарт накопилось 8 процессов веба. **Правило:**
  сигнатура остановки обязана ловить и супервизора (по имени его скрипта).
- **Два PR (приложение и транспорт раздельно).** Транспорт без правки
  приложения публикует операторский интерфейс на публичном домене.
  Промежуточного состояния быть не должно — поэтому **один PR**.

## Открытые вопросы для пользователя

1. **Память машины перед ночью.** В 12:55 свободно было 475 МБ из 16 144
   (97 % занято: MiniMax Code ~4 ГБ, браузер ~2,2 ГБ, WSL ~0,9 ГБ), к вечеру
   поднялось. Это **ваше решение** — закрыть лишние сессии. Без этого ночной
   срез может закрыться платными откатами в DeepSeek вместо локального движка.
2. **Воркеры и beat — тоже без входа в систему?** Сейчас они по-входовые:
   CLI-движок MiniMax и консольные инструменты ждут интерактивную сессию.
   Если нужно, чтобы и публикации шли без входа, — это отдельное решение
   (перевод на S4U) и отдельная проверка.
3. **MAX-уведомления о заявках.** Код готов и fail-soft, но в env нет
   `MAX_TOKEN`/`MAX_CHAT_ID` — канал молчит (P230). Telegram работает.
4. **Две тестовые заявки в базе** — закрыть в `/ad` → «Заявки с сайта» или удалить.
5. **Язык commit-сообщений** (не закрыт с прошлой сессии): канон требует
   английский, история репозитория — русская. Здесь по практике репозитория.
6. **Старый VPS** теперь держит публичный сайт — удалять его нельзя (обновлено в P249).
