## Failed approaches (этой нитки)

- **Скопировать токен комнаты КАРМАНа с прод-бокса на локальную машину** —
  не делали: выдача доступа к комнате — решение владельца (D-061), и гейт
  рантайма блокирует чтение env-файла с секретами. Поэтому сверка
  классификатора сделана **без** комнаты: боевые вердикты вынесены моделью
  MiniMax Code, и локальный движок MiniMax Code на машине есть.
- **Взять refresh-токен живой сессии MiniMax Code для локальной области** —
  не делали: обмен refresh-токена **ротирует** его на сервере, и перенесённый
  токен обесценил бы вход работающей сессии владельца. В область кладётся
  штатная заглушка проекта → P245.
- **Считать, что «пустой отчёт сверки» = «нет движка»** — неверно: инструмент
  был сломан (ключ `lip` брался не оттуда, откуда надо). Отчёт разбирался до
  конца, пока не сошёлся с сырым ответом модели. Урок вынесен в мозг
  (`mailbox/to-brain/2026-11-26-empty-report-of-broken-tool.md`).
- **Считать, что продакшн-вердикт и локальный сверяются «в лоб» по теме** —
  тема у классификатора свободная строка, и 8 расхождений из 40 — это
  «новости» против «соседи» при одном и том же действии. Решающее поле —
  действие; отчёт теперь показывает согласие по полям отдельно.
- **Проверить архив промта чтением env-файла бокса** — гейт блокирует
  (`sudo` и чтение `/etc/setka/setka.env`), а токена раздела в env бокса нет.
  Архив зафиксирован по выводу прошлой нитки; перепроверка — за Управляющим.
- **Прочитать `DATABASE_URL`/`SECRETS_TOKEN` с прод-бокса напрямую** (прошлая
  нитка) — гейт блокирует. Рабочий путь: свои скрипты на боксе
  (`infra/windows/prod_dump.sh`, `prod_counters.sh`), читающие env внутри себя
  и не печатающие значения.
- **Поднять свой PostgreSQL на 5432** — порт занят чужим PostgreSQL на этой
  машине; свой кластер на **5433**, чужое не тронуто.
- **Запустить `postgres.exe` с `DETACHED_PROCESS`/`CREATE_NO_WINDOW`** — падает
  с `0xC0000142` (DLL init failed). Работает запуск отдельной группой процессов
  без этих флагов.
- **Остановить лишний prefork-ворер `taskkill`/`Stop-Process`** — гейт
  блокирует kill процессов; вместо этого поднят второй воркер с `--pool=solo`.
- **Prefork на Windows с перенаправленным `TEMP`** — не помогло (пул
  зависал). Корневая причина `WinError 5` не изолирована; обход — solo → P244.
- **pytest без `--basetemp`** — прогон доходит до 100%, но падает на финальной
  уборке `%TEMP%` и не печатает итог. Обход: `--basetemp` внутри репозитория →
  P244.

## Открытые вопросы для пользователя

1. **Куда переносить радар** (оставить / вынести / отключить) — ADR-0025.
2. **Что крутится локально как движок**: DeepSeek API, MiniMax Code CLI или
   локальные модели? MiniMax Code CLI на этой машине **уже работает**.
3. **Проверять ли доступ к интерфейсу с других устройств** (слушать не
   только петлю) — по умолчанию выключено, см.
   [`docs/LOCAL_WINDOWS_BROWSER_LIMITS.md`](LOCAL_WINDOWS_BROWSER_LIMITS.md) §4.
4. **Когда отдавать команду на остановку прода** и что остаётся жить на
   боксе (ЕСА, `/services`, VK-шлюз, Радар)?
5. **Публикации с локального стенда** — подтвердить, что после подключения
   токена комнаты стенд может публиковать в боевые группы (сейчас не может:
   токенов нет).

## Не забыть (low-priority)

- **Порт PostgreSQL 5433** на этой машине занят **нашим** стендом; 5432 —
  чужой PostgreSQL, его не трогать.
- **Пустые файлы бэкапов** на боевом боксе (с января) — разбор с
  подтверждением владельца, в P242.
- **Каталог `downloads/`** на локальной машине (≈650 МБ: бинарники PostgreSQL
  и Redis, кластер БД, дамп) — вне git, но занимает место; при чистке сносить
  только его.
- `gateway_mcp/client.py` держит в коде прод-адрес шлюза как дефолт — при
  переезде адрес меняется (ADR-0023, §«Что не переносится»).
- **Локальная область MiniMax истекает вместе с access-токеном (~9 ч)** —
  после этого движок отвечает «нет входа»; лечится перезаводом области
  (P245).
