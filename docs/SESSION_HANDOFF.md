## Failed approaches (этой нитки)

- **Параллельные сабмиты тяжёлых пачек** (подтверждено 07.10): только последовательно (`submit` одной пачки за раз).
- **Воркер упал по rate limit провайдера** (`batch2` 09.10): лечится перезапуском воркера (`systemctl restart setka-celery-worker`), данные fetch на месте.
- **Транслит в хотлайн** (07.10): первое сообщение ушло транслитом; проверка показала UTF-8 чисто; переотправлено по-русски. Правило: после `send` перечитывать ленту глазами (уже в спеке).
- **«25 прогонов в день»** — неверная рамка владельцу: 3–4 марафона покрывают суточный флоу (~3200 постов/сутки), т.к. повторные заборы тянут следующие без вердикта.
- **Очередь — флоу, не сток** (замер 08.10): total kept-без-вердикта — архив аудита (тысячи), живая очередь — fresh 24ч (~3200/сутки по сети). Остановка марафонов — по усталости оператора или по решению о `P194`.
- **Fetch перезаписывал `pending.json`** (10.10, исправлено): каждый `fetch` в тот же каталог перезаписывал данные предыдущих пачек. Исправлено: `b1`, `b2`, `b3`, `b4` в отдельных каталогах (`pilot_run1_b1/2/3/` + оригинал `pilot_run1`).
