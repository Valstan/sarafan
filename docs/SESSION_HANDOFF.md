### 1. Discovery: чужие области в очередь не попадают (PR #1233) — выкачено

Аудит 23.11 (P235) показал: 329 кандидатов в очереди модерации — группы из чужих
областей (Москва, Владимир, Ярославль). Цепочка из трёх звеньев; два закрыты кодом:

- **area-guard:** у группы берётся VK-город, его область — через `database.getCities`;
  город из чужой области отбрасывается. Область региона — по городу области
  (родитель-регион), иначе по городу-центру. Неизвестный город остаётся.
- **fail-closed фильтр:** у 62 регионов из 81 список нп пуст, и фильтр там был
  выключен целиком — теперь фильтр применяется всегда (нет нп → требуется центральный
  стем).
- **кандидат без вердикта ИИ в очередь не идёт** (раньше вставлялся с пустыми `ai_*` —
  именно эти 329 строк полгода и лежали).

Отчёт прогона отдаёт числа: `found_total`, `dropped_foreign_area`,
`dropped_irrelevant`, `area_guard_off`.

### 2. Discovery на MiniMax не отработал НИ РАЗУ (PR #1234) — выкачено

Ночь 24.11 04:00 — первый настоящий прогон нового пути после переключения 23.11:
**MiniMax не ответил ни разу**, 385 `exec_failed` за сутки, весь ночной срез ушёл на
**платный Дипсик**. Причина: `ai_categorizer._call_minimax` звал MiniMax **без
системного промта**, а CLI пустой файл промта не принимает
(`--system-prompt-file ... is empty`).

Починено: промт разделён на **системный** (роль + список категорий + форма ответа) и
**карточку** сообщества; MiniMax получает системный промт файлом, карточку —
вложением, промт Дипсика не изменился. Плюс `minimax_engine.run_classification` с
пустым промтом больше не зовёт CLI, а отвечает `empty_system`.

⚠️ **Проверка ещё не закрыта:** срез 25.11 04:00 — первый, где новый путь должен
отработать. Строка в TICKLER на 25.11.

### 3. Продление входа MiniMax — **сработало** (проверка 24.11 закрыта)

Счёт не взялся из прошлой сессии: аккаунт сменился (**#3 → #105**, 23.11 18:48), срок

⚠️ Прибор на боксе сначала ответил «не проверено» — на проде была **старая версия**

## Failed approaches (этой нитки)

- **Дать `loc:`-поиску `city_id`** (буквальный совет из P235) — нельзя: мелкие сельские
  паблики помечены городом-центром района или «не задано», фильтр по `city_id` их
  потерял бы. Взят **ограничитель области** (area-guard) — город группы против области
  региона. Не повторять `city_id` в `loc:`-запросах без новой инфы.
- **Исключить курируемые источники (репосты и «Ссылки» главной страницы) из жёсткого
  фильтра** — откатил: это осознанное решение проекта (тест
  `test_discover_info_repost_results_go_through_relevance_filter`), репост областного
  паблика главной страницей района — не наш паблик.
- **Ждать срока токена из прошлой сессии (24.11 05:02)** — аккаунт сменился 23.11
  18:48 (#3 → #105), реальный срок был 06:48:36. Точку брать из живой машины.
- **Верить прибору на проде до выката** — прибор был старой версии (правка #1227 не
  задеплоена) и врал «не проверено» при сработавшем продлении. Выкат починил и
  прибор, и вердикт.
- **Гонять полный `pytest` через пайп `| Select-Object -Last 15`** — вывод не виден
  часами, непонятно, идёт ли прогон. Направлять в файл и смотреть по мере роста.
- **Ждать «первого вызова после истечения», чтобы прибор увидел продление** — прибор
  ищет продление *после* срока, а движок продлевает *до* срока: в норме «вызовов
  после истечения» не бывает. Учтено в правке PR #1227 (выкачена 24.11).
