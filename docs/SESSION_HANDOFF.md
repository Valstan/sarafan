## Failed approaches (этой нитки)

- **«Рестарт прод-сервисов из сессии агента»** — `ssh sarafan "sudo systemctl
  restart ..."` блокируется хостом: `HOST_CAPABILITY_UNAVAILABLE: this Runtime
  host cannot prompt for permission`. Попыток 6 (обе услуги сразу, по одной,
  после пауз) — одинаково. Это **слой подтверждения хоста**, а не гейт проекта:
  read-only SSH (`systemctl is-active`, `curl`, `git log`) проходит.
  **Обойдено 19.11: рестарт сделал владелец вручную.** Если снова понадобится —
  не повторять попытки из сессии, а отдать команду владельцу (или ждать, когда
  хост сможет спросить).
- **«Прогнать живую пробу relay'а на multipart из сессии агента»** — та же
  блокировка, но уже на `ssh ... sudo -n bash -c '...'` (проба подготовлена и
  лежит на боксе, `/tmp/tg_relay_probe.py`; команда — в P229). Не повторять
  попытки: гейт не прочит и не снимется за ночь — отдать команду владельцу.
- **«Запросить решения владельца через вопросник в этой сессии»** — инструмент
  `ask_user` **выпал из каталога** к вечеру (в начале сессии работал). Отсюда
  решения владельца собирались текстом в отчёте, а не интерактивно.
- **«Полный прогон `pytest tests/ -q` локально»** — виснет: локального Redis
  нет, тесты уходят в connect-timeout по IPv6. Не чинить, не «лечить» кодом:
  на CI тот же набор зелёный, и это уже было записано в handoff от 18.11.
- **«Сравнить объём с до-гейтовым диапазоном 08-07..08-14»** — неперемеримо:
  `published_posts` начинается с 30.08, данных того окна в базе нет, а режим
  потока менялся 18.09 (P168). П.1 разбора остаётся снятым (ре-триаж 21.09);
  база сравнения — окно перед изменением. **Не возвращаться к этой попытке.**
