### Движок: DeepSeek вместо self-hosted OpenCode (решение владельца 06.11)

Прод переведён на **DeepSeek API напрямую**: `CLASSIFIER_ENGINE=deepseek`, из env
убрано всё от контура (`OPENCODE_*`, `NEURAL_EGRESS_*`), добавлен
`CLASSIFIER_PREPUBLISH_MIN_CANDIDATES=5`. Ключ DeepSeek лежит в комнате КАРМАНА и
приезжает bootstrap'ом; баланс — **$19.99, `is_available: true`**, живой вызов — 200
(модель отвечает как `deepseek-flash`).

**Замер на живых постах (199 постов пачки 3, настоящие постулаты):** 20 чанков по
9–10 постов, **4,2–4,4 с на чанк**, префикс-кэш — 0 % на первом вызове, **82,5 %** и
**84,9 %** на следующих. Префикс (14 208 токенов) стабилен байт-в-байт: постулаты
идут системным сообщением, посты — пользовательским. На проде в логе воркера идут
строки `deepseek-usage label=headless model=deepseek-flash` с кэшем 54–98 %.

**Темп — реальное время.** Headless-таска переведена с «каждые 3 часа на :35» на
**ежечасно на :12** (код, `tasks/celery_app.py`), порог кандидатов для волны — с 15
на **5** (env). Минута :12 выбрана с зазором от всех тяжёлых слотов (волны :05/:07/
:20/:30/:37/:40/:45/:47/:50, тройка уведомлений :15/:28/:57, сканеры рекламы
:25/:55 и :05/:35).

**Модель закреплена за DeepSeek Flash 4.1** (заказ владельца 07.11). В каталоге
провайдера ровно две модели: `deepseek-flash` (DeepSeek-V4.1-Flash) и
`deepseek-v4-pro`; владелец: «v4-pro дороже и слабее, новый флеш 4.1 — наш».
Раньше стоял алиас `deepseek-chat` — это маршрутизация провайдера, а не модель:
её можно сменить молча, и движок уедет на другую по цене модель, не спросив
никого. Теперь `DEEPSEEK_MODEL=deepseek-flash` на проде и тот же дефолт в
`config/deepseek.py`; клиент сверяет имя модели из ответа с запрошенным и пишет
в лог предупреждение при расхождении, в БД ложится фактическое имя. Замер
07.11: запрошено `deepseek-chat` → отвечено `deepseek-flash`; запрошено
`deepseek-v4-pro` → отвечено оно же. **Три вызова `deepseek-v4-pro` на дашборде
не наши** — движок такого имени не просит нигде (второй проект владельца).

⚠️ **Явное имя включает «раздумья», а они съедают бюджет ответа.** Модель по
умолчанию рассуждает (effort = high) и на нашем промпте тратит на рассуждение
весь `max_tokens` (240 на пост): `finish=length`, вердиктов 0. Два прогона подряд
(01:50 и 02:12) дали **82 и 74 вердикта из 200** при 2,0 млн токенов вместо
200/200 и ~850 тыс. Документированные `reasoning_effort=low|high|max` не помогают
(вердиктов 0) — работают только `reasoning_effort=none` и
`thinking={"type":"disabled"}`. Выбран `thinking` (Anthropic-совместимое поле,
каталог провайдера объявляет `anthropic_messages`), дефолт `DEEPSEEK_THINKING=off`
в коде. Клиент предупреждает в лог, когда весь бюджет ушёл в рассуждение:
иначе виден только «много отказов» без причины. Проверка на проде после починки:
**200/200 вердиктов, 0 отказов, 855 тыс. токенов**.

**Контур снесён (гейт #025 получен от владельца):** сняты юниты `opencode-web`,
`neural-vpn`, `privoxy`, `privoxy-cleanup`, `opencode-rss-guard`,
`neural-egress-guard`; погашены `neural-egress-redirect`, `xray`, `xray@`. Удалены
бинари `opencode` (212 МБ) и `xray` (37 МБ), geo-базы xray, `/home/opencode`,
`/etc/opencode-web`, `/etc/neural`, `/usr/local/lib/neural`, npm-кэш root, старые
прогоны в `/tmp`, ротированные логи; пакет `privoxy` вычищен; пользователь `opencode`
снят. Освобождено **688 МБ диска (57 % → 49 %) и 643 МБ RAM** (доступно 786 МБ вместо
146). **Код в репо оставлен** — откат это `CLASSIFIER_ENGINE=opencode` плюс подъём
юнитов по `infra/neural/README.md`.

Канон: [ADR-0014](adr/0014-dvizhok-deepseek-pryamoy-selfhost-kontur-vyveden.md),

## Failed approaches (этой нитки)

- **`fetch_pending(limit=100000)` на проде падает:** список lip'ов в `IN`-запросе
  упирается в лимит параметров PostgreSQL (`the number of query arguments cannot
  exceed 32767`). Для точечной разметки — выборка по lip'ам прямо из
  `collected_post_audit`, без всей очереди.
- **Правка env-файла на боксе через `sudo bash -c "…"` из PowerShell ломается:**
  кавычки съедаются оболочкой. Рабочий путь — скрипт-файл, `scp` на бокс и
  `ssh sarafan 'bash /tmp/script.sh'`; файлы писать без BOM (иначе `#!/bin/bash`
  не запускается) и с LF.
- **Отсутствие `DEEPSEEK_API_KEY` в `/proc/<pid>/environ` — не доказательство
  отсутствия ключа:** процесс задаёт переменную уже после старта (bootstrap из
  vault), а `/proc/environ` показывает только исходное окружение. Проверять
  живым вызовом API, а не чтением окружения.
- **Создание/правка групп ВК через API не работает**: у живого токена `VALSTAN` в таблице
  `vk_tokens` scope только `wall.read` и `groups.read` — `groups.create` и `groups.edit`
  возвращают ошибку 3 «Unknown method passed». Переменная окружения `VK_TOKEN_VALSTAN` в
  `/etc/setka/setka.env` мёртвая (ошибка 5, просрочена 12.10) — живой токен лежит в БД
  (`vk_tokens`, `name='VALSTAN'`). Починка env-переменной — отдельная задача.
- **Форма настроек группы ВК не сохраняет поля, пока не выбрана activity** («Укажите тематику
  сообщества»): адрес, описание и город вводятся, но «Сохранить» их откатывает. Обход —
  создать группу через модалку, где activity «Городское сообщество» ставится сразу, иначе
  группа остаётся «Публичной страницей» с закрытой стеной.
- **Проверять отзыв старого ключа через `sudo`-команду нельзя.** `sudo` на боксе пишет полную
  командную строку в `/var/log/auth.log` — проверка «старый → 401» сама кладёт отозванное
  значение в системный лог. Значение надо передавать через переменную окружения, а не через
  аргумент. Лог системный, мы его **не трогали** — правка журнала аудита это решение владельца.
- **Тесты вечернего сборника были привязаны к стенным часам** (07.11, гейт CI упал на
  `main` — 7 тестов в `tests/test_publisher/test_daily_digest.py`): `collect_candidates`
  и `collect_photo_candidates` без `since` режут по **московским суткам** (начало суток =
  21:00 UTC), а фикстура клала пост «два часа назад» — между 00:00 и 02:00 МСК он оказывался
  за границей окна, и отбор пустел. Продукт прав, тесты краснели каждую ночь на два часа.
  Починено: окно в тестах задаётся явно (`_window()`), а контракт «окно по умолчанию = московские
  сутки» закрыт отдельным тестом, не зависящим от часа (`day_start_utc()` ± полчаса).
- **Воркеры-субагенты на общем лимите аккаунта** — четыре ребёнка умерли разом
  (`insufficient balance (1008)`), три куска потеряны, спасся только тот, что успел записать файл.
  **Не повторять**: разбор — последовательно в теле сессии, кусками с записью на диск.
- **Глобальный прокси на боксе — нельзя вслепую:** меняет IP выхода для публикации в VK, а на
  этом выходе держится идентичность проекта и квота аккаунта.
