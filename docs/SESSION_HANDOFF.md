## Текущая нитка

**MiniMax-контур: отказ «Sign in to MiniMax» был не про аккаунт, а про наше состояние
сессии CLI — а движок трактовал его как «аккаунт мёртв», что ежедневно съедало пул.**
22.11: **118 выдач аккаунтов при 0 успешных вызовов**, трафик ушёл в платный Дипсик
(579 вызовов). Причина: рантайм CLI держит сессию в `auth-state.json`; когда истёк
access-токен (12 ч), CLI не смог продлить цепочку (настоящего refresh нет — Карман
отдаёт только access) и перевёл сессию в `anonymous` — дальше любой запрос отвечал
«войдите», и каждый отказ стоил нового аккаунта.

**Починено и выкачено (оба фикса в бою с 23.11 09:52):** движок пишет состояние
сессии вместе с токеном; на `auth_expired` — продлевает **тот же** аккаунт через
ручку `renew` Кармана; «панель не прочиталась» (401 на протухшем токене) больше не
читается как «очков нет». Утренняя волна 23.11 прошла целиком на MiniMax:
**83 + 42 + 9** успешных вызовов за 07–09 МСК, **0 отказов, 0 новых аккаунтов**.

**Осталось проверить:** в **11:23 МСК** истекает access-токен аккаунта #197 — должно
сработать продление того же аккаунта. Если вместо продления движок возьмёт новый
аккаунт, причина — **409 от Кармана**: аккаунт #197 выдан 22.11 под журнальным
проектом `setka`, а `renew` сверяет владельца аккаунта с проектом комнаты `SARAFAN`.

## Следующий шаг

1. **Проверить продление входа (после 11:23 МСК)** — по логу воркера и журналу расхода:

   ```bash
   ssh sarafan "cd ~/SETKA && grep -a 'вход аккаунта .* продлён' logs/celery-worker.log | tail -3; grep -a 'Карман выбрал аккаунт' logs/celery-worker.log | tail -3"
   ```

   Ожидание: строка «вход аккаунта N продлён» и **ноль** новых выдач. Если взяли новый
   аккаунт — это 409 (см. выше), стоит **один** аккаунт; дальше renew работает (новые
   выдачи идут под проектом `SARAFAN`). Зафиксировать в
   [P227](pending/P227-minimax-kontur-pul-ak-kuntov-avtochekin.md).

2. **P234 — вечерняя сводка** (решение за владельцем): по замеру 22.11 чинит **веер**
   (задача на регион); слот сводка держит **час**, сборник выходит примерно для трети
   сети. Немедленная мера — `DAILY_DIGEST_ENABLED=0`.

3. **Карман — контракт `renew`:** правило «продлевать может только та комната, которой
   отдали аккаунт» сверяет журнальный проект выдачи с проектом комнаты. Аккаунты,
   выданные под другим журнальным проектом (у нас — все 128 выдач 22.11 под `setka`),
   продлить нельзя — 409. Письмо в мозг отправлено; если правило нужно смягчить — это правка
   на стороне Кармана.

## Failed approaches (этой нитки)

- **Сбросить сессию CLI удалением `auth-state.json`** — не помогает: CLI не пересобирает
  сессию из токен-стора сам. Помогает только состояние `authenticated`. **Не повторять**
  без новой инфы.
- **Дописать в запись токена `subject`/`accountId`** (поля, которые требует валидатор
  CLI) — не помогает: валидатор применяется к записи, которую CLI строит **сам** при
  входе, а не к нашей. Проверено живьём — отказ тот же.
- **Продлить access по refresh-токену из стора** — невозможно: Карман refresh наружу не
  отдаёт (мандат владельца 14.11), движок пишет заглушку
  `mmoat_placeholder_refresh_not_provided`. Продлить цепочку может только владелец
  пула — ручка `renew`.
- **Живая проба пула (`scripts/minimax_pool_probe.py`)** — не выполнена: гейт инструмента
  сессии не пропускает чтение env-файлов с секретами. Все числа взяты из БД Кармана и
  журналов прод-бокса.
- **Ротация по классу отказа, который не про ресурс** — снимает ресурс: каждый отказ
  вида «Sign in» / «панель 401» стоил одного аккаунта (118 за сутки 22.11).
