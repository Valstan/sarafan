# Мост к локальному движку: как это устроено и как запустить

> Решение владельца 10.11.2026: локальная нейронка на ПК владельца — основной
> движок классификации, DeepSeek по необходимости (локальная недоступна или
> пропустила волну). Основа — мандат мозга от 09.11 («мост по схеме Pull,
> старт в тени; сначала сжать правилник»).

## Что построено (10.11)

| Файл | Где живёт | Что делает |
|---|---|---|
| [`modules/classifier/local_engine.py`](../../modules/classifier/local_engine.py) | бокс | общая логика: выгрузка батча, приём вердиктов, журнал прогонов, статистика для панели |
| [`scripts/local_bridge.py`](../../scripts/local_bridge.py) | бокс | CLI: `export` (батч + промпт) и `submit` (приём вердиктов) |
| [`scripts/local_bridge.sh`](../../scripts/local_bridge.sh) | бокс | обёртка: грузит env приложения и зовёт CLI (env-файл root-only, поэтому `sudo`) |
| [`scripts/local_engine_daemon.py`](../../scripts/local_engine_daemon.py) | **ПК владельца** | демон: тянет батч по SSH → считает локально → отдаёт вердикты; только стандартная библиотека |
| [`scripts/local_engine_opencode.py`](../../scripts/local_engine_opencode.py) | **ПК владельца** | клиент к opencode v2 (сессионная схема serve: `/api/session` → prompt → wait → message) |
| [`scripts/local_engine_probe.py`](../../scripts/local_engine_probe.py) | **ПК владельца** | прогон золотой выборки через локальный движок (для теневой сверки) |
| [`scripts/classifier_local_shadow.py`](../../scripts/classifier_local_shadow.py) | бокс | теневая сверка: локальная модель против облака на одних и тех же постах |
| [`web/api/local_engine.py`](../../web/api/local_engine.py) + [`web/templates/local_engine.html`](../../web/templates/local_engine.html) + [`web/static/js/local_engine.js`](../../web/static/js/local_engine.js) | бокс | панель `/local-engine`: движок, качество, обучение |

## Схема Pull

```
ПК владельца                        бокс SETKA
─────────────                        ──────────
демон (по расписанию)
  │  ssh sarafan "sudo -n ~/SETKA/scripts/local_bridge.sh export --limit 20"
  │ ─────────────────────────────────►  отдаёт посты БЕЗ вердикта + тот же промпт,
  │ ◄─────────────────────────────────  какой получает облачный движок
  │
  │  локальная модель (OpenAI-совместимый API)
  │
  │  ssh sarafan "sudo -n ~/SETKA/scripts/local_bridge.sh submit" < verdicts.json
  │ ─────────────────────────────────►  запись вердиктов НАШИМ кодом (идемпотентно по lip)
```

Инициатива всегда на стороне ПК — домашний компьютер не нужно делать видимым из
интернета. Ключ от бокса демону не нужен: только SSH.

**Тождество промпта — условие честного сравнения.** `export` отдаёт ровно тот
system-сообщение (задача + эффективные постулаты) и тот же user-промпт, что
уходит в облако. Локальная модель отвечает на тот же вопрос, что и DeepSeek.

**Почему не HTTP-эндпоинты, а SSH.** HTTP-контракт классификатора
(`/api/classifier/pending`, `/postulates`, `/verdicts`) существует с времён
облачной рутины и подходит. Но env-файл приложения root-only, а ключ ingest
хранится на боксе; демон на ПК забирать его не должен. Через SSH бокс сам
отдаёт батч и сам принимает вердикты — ключ на ПК не появляется, а
инициатива остаётся на стороне ПК.

## Фолбэк: почему DeepSeek сам собой отходит на второй план

Ключ `lip` в `content_classifications` уникален: вердикт на пост ровно один.
Кто первый классифицировал — тот и записал. Поэтому:

* демон ходит чаще, чем часовой прогон бокса → посты забирает локальный движок,
  а облачный headless находит очередь пустой и **не тратит токены**;
* если ПК выключен, демон упал или не успел — посты остаются без вердикта, и их
  забирает облачный headless. **DeepSeek подключается ровно тогда, когда локальный
  движок не справился** — это и было задумано.

Побочный эффект: источник вердикта теперь виден (`source` = `local` / `headless`),
поэтому качество можно сравнивать по движкам, а не «вообще».

## Волна на free-тире, платный Дипсик — страховка (решение владельца 11.11)

ADR-0015. Переключатель `CLASSIFIER_ENGINE` выбирал **один** движок: на
исчерпанной квоте free-тира волна оставалась без вердиктов. Теперь отказ
free-тира закрывает **платный Дипсик** на том же чанке, а когда квота
сбросится, следующий вызов снова пойдёт в free-тир.

Что должно стоять в env-файле бокса (`/etc/setka/setka.env`):

```text
CLASSIFIER_ENGINE=opencode                 # free-тир основной
CLASSIFIER_PAID_FALLBACK=1                  # платный Дипсик — страховка
OPENCODE_BASE_URL=http://127.0.0.1:4097     # адрес serve (дефолт в коде 4096!)
OPENCODE_NO_SPAWN=1                         # второй opencode на 1,5 ГБ не поднимаем
OPENCODE_PUBLISH_TIMEOUT=120                # free-модель медленнее: 10-25 с на пост
CLASSIFIER_HEADLESS_CHUNK=5                 # чанк волны под free (было 40 под Дипсик)
CLASSIFIER_HEADLESS_REGIONS_PER_CHUNK=2     # склейка merge_with судится внутри района
```

Читать в логе воркера:

```text
headless: free-тир не ответил (quota_exhausted) — закрываем чанк платным Дипсиком
headless: предохранитель free-тира открыт — закрываем платным Дипсиком
```

**Пароль serve.** `opencode serve` перевыпускает пароль при каждом рестарте,
поэтому в env-файле он устаревает молча (401 на каждом вызове). Клиент берёт его
из файла, который serve пишет сам: `~/.config/opencode/service.json` — тот же
файл читает демон моста.

**Когда free-тир жив.** Замер 11.11 по демону: надёжно отвечает **03–05 UTC**
(06–08 МСК), к 18 UTC (21 МСК) квота уже мертва (`quota_exhausted http_429: Free
usage limit reached`). То есть «следующие сутки» — это раннее утро, а не полдень:
волны с 03:12 UTC пойдут бесплатными, дальше — платный Дипсик.

**Откат** — одна переменная и рестарт: `CLASSIFIER_ENGINE=deepseek`. Если платить
нельзя (счёт пуст) — `CLASSIFIER_PAID_FALLBACK=0`: волна идёт по обычным
фильтрам, а не тратит.

## Панель `/local-engine`

* **Движок** — прогоны демона: когда, сколько постов, сколько вердиктов, сколько
  записано, сколько длилось, ошибки (пустой круг тоже пишется — иначе «демон
  молчит» не отличить от «очереди нет»);
* **Качество** — согласие оператора отдельно по облаку и по локальной модели
  (`action` и `theme`) + **недельные окна**: растёт ли качество;
* **Обучение** — коррекции по неделям и судьба выученных правил (предложено /
  утверждено / отклонено / выведено);
* **Вердикты по источникам** по дням за 30 дней.

Панель закрыта входом оператора, как весь SETKA (`middleware/auth_gate.py`):
без сессии — 401 на API и 302 на страницу. Это не обход гейта, а его нормальная
работа: страницу видит только владелец.

## Движок: где стоит и как поднят (замер 10.11)

**Локальной llama-модели нет** — весов (`.gguf`) и рантаймов (`llama-server`,
`ollama`, LM Studio) на машине владельца нет, а на боксе тем более (там 1,5 ГБ
RAM). Но есть **OpenCode v2.1.4** с free-тиром моделей
(`opencode/deepseek-v4.1-flash-free` и другие) — тот контур, что до ADR-0014
работал на боксе.

**Важно, что это не локальная модель, а free-тир облака.** Деньги DeepSeek при
этом не тратятся (значит, цель P224 достигается), но надёжность — не как у
локального llama: лимиты аккаунта, гейты по IP, отказы цепочки. Поэтому
переключение делается **в тени** и по факту сверки.

**OpenCode v2 — не OpenAI-совместимый сервер.** У него своя схема:
`POST /api/session` (сессия сразу с моделью) → `POST /api/session/{id}/prompt`
(сообщение в очередь) → `POST /api/experimental/session/{id}/wait` (тишина) →
`GET /api/session/{id}/message` (текст в `content[type=text]`, счётчики в
`tokens`) → `DELETE /api/session/{id}` (сессия убирает себя). Ролевых частей у
serve нет: постулаты и посты уходят одним сообщением.

Клиент к этой схеме — `scripts/local_engine_opencode.py` (только стандартная
библиотека, как и демон). Пароль serve сервер пишет сам при старте в
`~/.config/opencode/service.json`; логин — `opencode`, авторизация basic.

### Где живёт движок (решение владельца 10.11)

**На боксе, а не на ПК владельца.** Классификация должна идти независимо от
того, включён ли компьютер. Развёртывание — `infra/engine/`:

| Файл | Что делает |
|---|---|
| `infra/engine/opencode-engine.sh` | обёртка: поднимает `opencode serve --service` и сторожит порт |
| `infra/engine/opencode-engine.service` | systemd-юнит обёртки (переживает перезагрузку, потолок памяти 512 М) |
| `infra/engine/local-engine.cron` | крона: демон раз в 5 минут, один круг (`--once`) |
| `infra/engine/README.md` | установка и проверка |

**Ключ на сервер не переносится:** free-тир отдаёт провайдер `opencode` с
публичным ключом, на боксе нужен только сам opencode. Замер 10.11:
`deepseek-v4.1-flash-free` ответила **с IP бокса**, гейта по IP нет (ADR-0014:
тогда тот гейт закрывал весь каталог — либо сменился адрес, либо правило
смягчилось; проверять надо было, а не предполагать).

Демон на боксе ходит в мост **локально** (`--local`), без SSH.

### Если движок нужен на ПК владельца (запасной вариант)

```bash
# 1. сервер движка (фоновый, на фиксированном порту)
opencode serve --service --port 4097

# 2. демон моста (боевой режим: вердикты пишутся в корпус с source=local)
python scripts/local_engine_daemon.py \
    --engine opencode --model-url http://127.0.0.1:4097 \
    --regions-per-chunk 2 --model-timeout 100 --interval 300
```

Автозапуск — Планировщик задач Windows (при входе в систему): две задачи,
«SETKA Local Engine - opencode serve» и «SETKA Local Engine - daemon». Ставится
одной командой:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup_local_engine_tasks.ps1
```

**Не запускать одновременно с боксом**: два движка делят одну очередь, и
кто первый записал вердикт по посту, тот и выиграл — лишняя работа и путаница
в источниках.

Демон сам переживает падение движка: волна уходит в облако (fail-open).
**Режим тени** — добавь `--shadow`: вердикты не пишутся в корпус, только отчёт
о прогоне.

**Почему `--regions-per-chunk 2`.** Free-тир-модель на большом чанке (8
регионов, до 40 постов) уходит в длинное рассуждение и не отвечает — замер
10.11: чанк из 23 постов молчал 11 минут. По два региона на вызов — быстро
(12–44 с) и стабильно. **Почему `--model-timeout 100`.** Зависшая модель в
цепочке съедает свой потолок и не пускает следующую (тот же класс, что
ADR-0014 для боевого контура).

**Проверка без модели:** `python scripts/local_engine_daemon.py --dry-run --once`
— покажет, какой батч он забрал бы.

**Замер 10.11 на живом промпте** (8,4K токенов постулатов + 8 постов):
`deepseek-v4.1-flash-free` ответила за 24,5 с, 8/8 вердиктов с разбором,
11 661 токенов промпта и 744 ответа — деньги DeepSeek не потрачены.

## Теневая сверка: локальная модель против облака

Инструмент — `scripts/classifier_local_shadow.py` (на боксе):

```bash
# 1. выгрузка: золотая выборка + облачный эталон + промпты для ПК
sudo bash -c 'set -a; . /etc/setka/setka.env; . /etc/setka/secrets-token.env; set +a;
    cd /home/valstan/SETKA && ./venv/bin/python
    scripts/classifier_local_shadow.py --dump-sample /tmp/shadow_sample.json --limit 120'

# 2. на ПК: те же промпты через локальный движок
python scripts/local_engine_probe.py --sample C:\\temp\\shadow_sample.json \
    --out C:\\temp\\local_verdicts.json --engine opencode --model-url http://127.0.0.1:4097

# 3. счёт: облако против локальной модели, попарно по одним и тем же постам
./venv/bin/python scripts/classifier_local_shadow.py \
    --score /tmp/shadow_sample.json --local /tmp/local_verdicts.json
```

Сравнение **попарное** (сколько постов прав только облако, сколько — только
локальная модель), а не сравнение двух процентов: модель не детерминирована
(temperature 0,2), и проценты гуляют на шуме.

**Измерение ничего не пишет** в корпус: ни одной строки в
`content_classifications` не появляется.

## Ограничения, о которых надо знать

* **Качество локальной модели на наших постах** — измеряется (`--dump-sample` /
  `--score` выше). Мозг мерял на прототипе: 18,2 % против 37–45 % у облака, но
  прототип и free-тир — разные вещи: решение принимается по факту сверки.
* **Free-тир — не локальная модель.** Лимиты аккаунта, гейты по IP и отказы
  цепочки реальны (ADR-0014 описывает весь этот класс на боксе). Отсюда режим
  тени и фолбэк на облако.
* **Склейка между регионами** в смешанном чанке отсекается кодом
  (`parse_chunk_response`), а не только промптом.
* **Отчёт о прогоне** пишется в `logs/local_engine_runs.jsonl` — это
  runtime-файл на боксе, не git.
