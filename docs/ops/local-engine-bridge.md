# Мост к локальному движку: контракт Pull (машина владельца → бокс SETKA)

> Проект: решение владельца 10.11.2026 — локальная нейронка на ПК владельца
> основной движок классификации, DeepSeek по необходимости (движок недоступен,
> волна пропущена, другой запрос). Основа — мандат мозга от 09.11
> («мост к локальному движку по схеме Pull, старт в тени; сначала сжать
> правилник»).

## Почему Pull, а не Push

Инициатива всегда на стороне ПК: демон на домашней машине **сам** ходит на
бокс по SSH и забирает батч. Значит домашний ПК не нужно делать видимым из
интернета — ни белого IP, ни туннеля, ни входящих портов. Простой ПК переживает
простой: волна без вердикта публикуется по обычным фильтрам (fail-open уже
встроен).

## Две нужные команды УЖЕ ЕСТЬ в HTTP-контракте

Со стороны SETKA **новый код не нужен**: интерфейс, который требует мозг,
существует с времён облачной рутины ([`web/api/classifier_ingest.py`](../../web/api/classifier_ingest.py)).

| Шаг | Запрос | Что делает |
|---|---|---|
| 1. выгрузка батча | `GET /api/classifier/pending?region=&limit=` | посты без вердикта: `lip`, `region_code`, `text`, `url`, `media`, метрики. Идемпотентно (только без вердикта), без прав в БД |
| 2. правила | `GET /api/classifier/postulates` | эффективные постулаты (база + словарь тем + выученные правила) — plain text |
| 3. приём вердиктов | `POST /api/classifier/verdicts` | запись вердиктов наш кодом: разбор толерантный, per-item; чужой/неизвестный `lip` → `skipped_missing`, дубль → `skipped_existing` |
| 4. вложения (опционально) | `GET /api/classifier/media?url=` | прокси вложений VK (для бестекстовых постов) |

Авторизация — заголовок `X-API-Key` со значением `CLASSIFIER_INGEST_KEY`
(на боксе лежит в `/etc/setka/classifier-routine-key.txt`, root-only). Ключ
достаётся локальным агентом по SSH от своего ключа — на ПК он не хранится.

## Что должен уметь локальный движок

Контракт промпта — **тот же**, что у боевого headless-пути
([`modules/classifier/headless.py`](../../modules/classifier/headless.py)):

- системное сообщение = задача + эффективные постулаты (байт-в-байт);
- пользовательское = посты чанка;
- ответ — JSON: `theme`, `action`, `merge_with`, `split`, `confidence`,
  `reasoning`;
- `temperature 0.2`, `max_tokens` = 240 на пост, строгий JSON-режим.

Движок — **OpenAI-совместимый** (`/v1/chat/completions`, `response_format:
json_object`): это и `llama-server`, и `opencode serve` — тот же контракт, на
котором мозг гонял прототип.

**Контекст.** Правилник сжат до ~9K токенов — это и было условием: с полным
(10,3K) локальный вариант даёт 25,7 ч на 1400 постов в сутки, со сжатым —
1,2 ч. То есть **сжатый правилник — не оптимизация, а условие работоспособности
локального движка**.

**Скорость.** Мозг мерил 79,65 ток/с декодирования и пик RSS 372 МБ против
2485 МБ у облака: на локальной модели **декод сжимается в ~24 раза**.

## Старт — в тени, переключение — по факту

Мозг измерил качество прототипа на настоящих правках оператора: локальная
модель совпала с оператором лишь в **18,2 %** случаев (облачная рутина на той
же выборке — 37–45 %). То есть локальный движок **наследует ошибки облака**,
и переключать ручку сразу нельзя.

Отсюда порядок (он же — порядок мандата):

1. **Тень.** Оба движка решают ОДИН И ТОТ ЖЕ батч, результаты сравниваются
   ([`scripts/classifier_headless_compare.py`](../../scripts/classifier_headless_compare.py)
   уже умеет считать согласие по `action` и `theme`).
2. **Порог.** Локальный движок признаётся основным, когда его согласие с
   оператором не хуже облачного на живой выборке правок.
3. **Переключение.** DeepSeek остаётся как фолбэк: локальный движок недоступен,
   волна пропущена, нужен другой запрос — тогда облако.

**Что при этом нельзя нарушать.** Fail-open: пост без вердикта публикуется по
обычным фильтрам. Локальный движок не имеет права «промолчать» о посте —
пропуск должен быть виден (волна уходит в DeepSeek), иначе «тихий» пропуск
станет модерационной дырой.

## Очередь и приоритет

Классификация стоит на пути публикации (`CLASSIFIER_ENFORCE_ENABLED=1`):
вердикты `delete`/`hold` не пускают пост в ленту. Значит локальный движок
обязан укладываться в окно волны — иначе волна уйдёт без вердиктов и
опубликуется «гладко», но неверно.

## Что осталось за владельцем

- Модель и железо на ПК (какая модель, сколько RAM, где живёт).
- Ключ ingest-доступа для локального агента.
- Решение по порогу переключения (шаг 2 выше).
