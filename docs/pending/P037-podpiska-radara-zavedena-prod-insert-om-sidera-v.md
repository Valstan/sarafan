Подписка `valstan→gonba_life` в `radar_subscriptions` заведена прямым прод-INSERT-ом вне git;
grep `radar_subscriptions` по `scripts/` и `database/migrations/` не даёт ни одного файла-сидера —
при пересборке БД подписка теряется молча, и поллер снова увидит `sources:0`. Env intake-бота
(`RADAR_BOT_NAME`, `RADAR_BOT_ALLOWED_USERS`) восстановимы — они перечислены в
`modules/secrets_bootstrap.py:119-120`; воспроизводима из репозитория только эта половина.

**Ре-триаж 19.11 — риск оказался пустым, запись закрыта.** Снято живое состояние с прода:

- **Подписки на проде:** три активные — «Пездуза» (tg), «Анатолий Шарий» (tg),
  «Управление инвестиционной и социальной политики» (vk). Все три живые: первые два
  приносят элементы ежедневно, ВК-источник — последний элемент 16.11 (публикует редко).
- **Подписки `valstan→gonba_life` больше нет** — и **источник «Гоньба» мёртв**: оба его
  источника (vk `-218688001` и tg `gonba_life`) не поллятся с 12.06 и 14.06. Источник
  без подписок поллер и не трогает — это и есть причина тишины.
- Значит, **восстанавливать нечего**: риск «тихой потери при пересборке БД» касался
  подписки на мёртвый источник. Если владелец захочет Гоньбу обратно, сначала нужно
  оживить источник (проверить канал), и только потом подписаться заново — из кабинета.
- **Сидер в git не обязателен** — по письму Мозга от 19.11 подписка создаётся из
  кабинета (`POST /api/radar/subscriptions`), это правильный путь, и состав подписок на
  проде дефектом не считается.
