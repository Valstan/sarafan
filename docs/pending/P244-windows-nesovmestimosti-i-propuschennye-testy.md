# P244 — Windows: две несовместимости с обходом и разбор пропущенных тестов

**Приоритет:** 🟡 техдолг (работает, но обходом)
**Открыто:** 2026-11-26 · `⏱ 2026-11-26 · snooze 0 · fresh`

## Симптом

Прогон `pytest tests/ -q` на Windows (26.11.2026): **5266 passed, 37 skipped,
0 failed**, собрано 5303. На Linux (CI после #1291 + 6 новых тестов этой
ветки): **5303 passed, 0 skipped** — те же самые 5303 собранных проверок.
То есть **ни один тест проекта на Windows не падает**, а расхождение
в числе собранных проверок объясняется полностью.

Но две вещи на Windows мешают и deserve отдельной записи.

## 1. Пул Celery: prefork не работает

**Симптом.** Воркер с пулом по умолчанию (prefork, `billiard`) рапортует
`ready`, но его дочерние процессы падают:

```
File "...\billiard\pool.py", line 406, in _ensure_messages_consumed
    if self.on_ready_counter.value >= completed:
PermissionError: [WinError 5] Отказано в доступе
[ERROR/MainProcess] Process 'SpawnPoolWorker-1' pid:880 exited with 'exitcode 1'
```

Воркер при этом продолжает «ready» и бесконечно перезапускает детей.

**Обход (работает).** `--pool=solo`. На боевом Linux остаётся prefork — там
он работает штатно. Соло-пул при `concurrency=1` даёт то же самое, что и
prefork с одним ребёнком, но без процесса-ребёнка.

Прописано в `infra/windows/start-worker.ps1` и
`infra/windows/start-wave-worker.ps1`; обоснование — в комментарии к скриптам
и в [`docs/AGENT_RUNTIME.md`](../AGENT_RUNTIME.md) §5.

**Что не выяснено.** Корневая причина не изолирована. Тот же `PermissionError:
[WinError 5]` вылезает при финальной уборке временных каталогов `pytest`
(пункт 2), то есть оба случая могут иметь одну причину — права на `%TEMP%` на
этой машине. Проверка с перенаправленным `TEMP` внутри репозитория
воспроизведения не сняла (пул зависал). Соло-пул — рабочий путь
независимо от причины; отдельного расследования не требуется, пока машина
не обслуживается другим администратором.

## 2. pytest: уборка временных каталогов

**Симптом.** Прогон доходит до 100% и падает на финальной уборке:

```
File "...\_pytest\pathlib.py", line 354, in cleanup_dead_symlinks
    if not left_dir.resolve().exists():
PermissionError: [WinError 5] Отказано в доступе:
  'C:\Users\<user>\AppData\Local\Temp\pytest-of-<user>\pytest-current'
```

**Это не тесты проекта, а pytest на этой машине.** Нумерация «собрано N,
зелёных M» при этом не печатается — прогон выглядит упавшим, хотя все
проверки зелёные.

**Обход (работает).** `--basetemp` внутри репозитория:

```powershell
.\venv\Scripts\python.exe -m pytest tests/ -q --basetemp=temp\pytest_win
```

## 3. Разбор 37 пропущенных на Windows

| Сколько | Что | Причина | Это проблема кода? |
|---|---|---|---|
| 36 | `tests/test_logging/test_decoy_corpus.py` | «gitleaks не найден: полоса scan НЕ ПРОВЕРЕНА» — на машине разработчика нет бинарника сканера секретов | **Нет.** В CI сканер установлен (отдельный шаг `secret scan`), там эти 36 проверок выполняются |
| 1 | `tests/test_opencode_engine.py:784` | «/proc доступен только на Linux» — тест читает `/proc` | **Нет.** Тест Linux-only by design; на Linux выполняется |

**Вывод.** Несовместимости с Windows в самом коде проекта не найдено: все
тесты, которые могут идти на Windows, идут. Расхождение 5303 собранных
против 5303 на Linux объясняется **двумя** вещами: 22 новых теста
(16 агентного слоя + 6 инструмента сверки классификатора) и 37 пропущенных
по среде (36 — отсутствие сканера, 1 — Linux-only).

## Что можно улучшить (не срочно)

* В `pytest.ini` можно задать `addopts` с `--basetemp` для Windows, чтобы
  обход не надо было помнить. **Не сделано:** путь `--basetemp` должен быть
  уникальным на прогон, иначе параллельные прогоны мешают друг другу —
  это требует аккуратной реализации (генерация имени), а не одной строки в
  конфиге.
* Починить уборку `%TEMP%` на машине (права/антивирус) — это часть
  эксплуатации машины владельца, не проекта.
