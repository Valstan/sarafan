# P247 — Домены `www.*` отдают 502: сертификат покрывает, а nginx не знает

**Приоритет:** 🟡 техдолг
**Открыто:** 2026-11-26 · `⏱ 2026-11-26 · snooze 0 · fresh`

## Симптом

Запрос к `www.сарафан.вмалмыже.рф`, `www.вход.…`, `www.радар.…`,
`www.валентин.…` и `www.вмалмыже.рф` возвращает **502**.

## Что найдено 26.11 (инвентаризация nginx)

* DNS ведёт `www.*` на боевой бокс, и **сертификаты `www.*` покрыты** (они
  есть в SAN выданных наружу сертификатов — их терминирует edge-провайдер).
* Но в nginx **нет ни одного `server_name` с `www.`** → такие запросы
  попадают в `default_server`, который отдаёт `444`/`ssl_reject_handshake` →
  edge отвечает 502.
* Подтверждено журналом nginx: `www.сарафан` — 8386 записей, `www.вход` —
  5895, `www.радар` — 2940, `www.валентин` — 2300, `www.вмалмыже` — 7110.

## Почему это отдельная запись, а не часть переезда

Дефект **не связан с переездом** и переживёт его как есть: сертификаты
выпускаются на edge, а маршрутизация `www.*` в nginx — нет. Переезд этого
не чинит, но и не ломает.

## Как чинить

Вариант: явные `server_name` с `www.` в соответствующих vhost'ах + редирект
на apex (или один блок на все `www.*`). Конфиги лежат в
`config/nginx_*.conf` — ставить оттуда, по правилу 4 в
[`ops/HOSTS.md`](../ops/HOSTS.md). Проверять редиректы **через nginx** с
живой сессией.
