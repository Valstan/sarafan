# P257 — Логи юнитов обнуляются на каждом старте: прошлая ошибка стирается, а в середине ночи остаётся дыра

**Приоритет:** 🟡 техдолг (на диагностику не влияет, но именно из-за него две ночи читались «дырами» в середине)
**Открыто:** 2026-11-27 · `⏱ 2026-11-27 · snooze 0 · fresh`

## Симптом

`Start-StandProcess` (`infra/windows/common.ps1:132-159`) перенаправляет вывод
процесса через `Start-Process -RedirectStandardOutput/-RedirectStandardError`, а тот
**создаёт файлы заново** при каждом старте. То есть лог юнита — это «хвост с
момента последнего старта», а не журнал.

Следствия, которые уже стоили времени:

| что | где видно |
|---|---|
| «address already in use» (11 экземпляров веба) **не остался ни разу** | [P255](P255-veb-stenda-lezhit-supervizor-plodit-ekzemplyary.md) |
| после рестарта 26.11 22:40 старый воркер продолжил писать в свой файл **со старого смещения** — в `logs/setka-wave-worker.err.log` образовался **NUL-разрыв** | [P256](P256-ostanovka-zadachi-ne-ostanavlivet-prilozhenie.md) |
| чтение такого лога даёт **дыру в середине ночи** — а ночь и есть время, когда смотреть | [P254](P254-proba-stenda-chitaet-ne-te-logi.md) |

## Почему это мешает

Диагностика боевого контура работает по логам. Если лог обнуляется на старте,
то после рестарта **первые минуты работы юнита не видны вообще** — а именно там
живут отказы, коллизии и «не поднялся второй экземпляр». Разрыв NUL вместо
лога — это вырожденный случай того же: два процесса пишут в один файл, каждый
со своего смещения.

## Что делать

1. **Писать с добавлением, а не с перезаписью.** `Start-Process` так не умеет —
   нужен обход: либо вести stdout/stderr в свой файл через собственный
   перенаправитель (например, `cmd /c "… >> log 2>&1"`), либо забирать вывод
   процессом-обёрткой и дописывать его в файл самому.
2. **Ротация по размеру** (как `logs/celery-worker.log.1` на боксе): держать
   `setka-worker.err.log` и предыдущий файл, чтобы «вчерашняя ночь» не
   исчезла целиком.
3. **Имя файла — с меткой запуска** (`setka-wave-worker.err.2026-11-27T0743.log`)
   либо ротация по времени: тогда рестарт не стирает прошлый запуск, а
   NUL-разрыв невозможен по построению.

## Проверка

- После рестарта юнита **старый** лог обязан остаться на диске.
- Два запуска подряд — два файла (или один с дописанным хвостом), без NUL-разрыва
  между ними.
- `Test-StandPortListening`/`Stop-StandProcess` (P256) не должны при этом
  ломаться: сигнатуры ищутся по командной строке, а не по имени лога.
