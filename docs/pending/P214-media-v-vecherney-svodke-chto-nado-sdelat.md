# P214 — медиа в вечерней сводке «Короткой строкой»: что именно нужно доделать

> Запись `P214` реестра [PENDING_FOLLOWUPS](../PENDING_FOLLOWUPS.md). Индекс грепается, запись читается целиком, реестр целиком не читается никогда ([D-097](../../AGENTS.md)).

`⏱ 2026-11-02 · snooze 0 · fresh · решение владельца не принято — ждём «делаем шаг 1»`

## Откуда вопрос

Заказ владельца 22.09 (P182): вечером выпускать один сборник из невышедшего — «что произошло
в общих чертах, своими словами, но без фантазий и перевирания», **с картинками/видео**
([ADR-0012](../adr/0012-vechernyaya-svodka-korotkoy-strokoy.md), п. «Заказ владельца 22.09»).

В первой версии медиа не прикрепляются — это зафиксировано в ADR-0012 п.7: «Тексты и отбор
работают; вложение постов с картинками — отдельная работа (нужен аплоад медиа в VK, которого
в конвейере нет). Владелец увидит сборники без картинок и решит, нужна ли эта часть».

Владелец сборники увидел (замер 01.11: 120 сборников, 589 пунктов, 0 неподтверждённых чисел,
0 дублей в ленте). Решение «нужна ли эта часть» — за ним.

## Что мешает сейчас

1. **В сборнике нет поля для медиа.** `modules/publisher/daily_digest.py`: `DigestDraft` = текст
   + список `lips`. Ни вложений, ни разбора медиа источника.
2. **Переиспользовать id фото источника, как это делает буллетин, для сводки не выйдет.**
   Буллетин (`modules/publisher/bulletin_builder.py`) прикрепляет фото источника его же
   идентификатором (`photo{owner}_{id}` через `utils/vk_attachments.py`) — это работает для
   сообществ, куда у нас есть права. Источники сводки — **чужие** сообщества: VK такой id
   не отдаст, фотографию надо **загрузить к себе** и приложить уже свой.
3. **Загрузка в конвейере есть только в одном месте** — `modules/ad_cabinet/vk_photo_upload.py`
   (`photos.getMessagesUploadServer` + сырой multipart). В publisher она не подключена.

## План (два шага, первый дешёвый)

**Шаг 1 — картинки к пунктам сборника (рекомендую).**

- Загрузка фото первых N пунктов в нашу группу через существующий `vk_photo_upload` (не
  изобретать новый механизм), затем `wall.post` с `attachment=photo<our_owner>_<id>`.
- N и правило выбора — решение владельца: предлагаю **фото первых 1–3 пунктов** (иначе
  десять картинок перебивают читателя), лимит `wall.post` — 10 вложений, но в сборнике
  держаться 3.
- Отказоустойчивость: фото не загрузилось → пункт выходит **без** картинки, сборник выходит
  всегда (как сейчас). Ошибка загрузки не должна ронять рубрику.
- Тексты источников в сборник не меняются, пунктов без текста по-прежнему не берутся
  (правило «нет текста — нет пункта» остаётся).

**Шаг 2 — пункты-без-текста (отдельное решение).** Сейчас пост только с фото в сборник не
попадает: пересказывать нечего, а голая ссылка на источник запрещена. Если владелец хочет
такие посты в сборнике, надо решить, как пункт будет выглядеть без текста (фото + название
источника + короткая подпись?), иначе рубрика по-прежнему их теряет.

## Оценка

Шаг 1 — фича на 3–5 рабочих дней (загрузка, ошибки, приёмка на проде, тест на пустом
медиа). Шаг 2 — отдельная, с редакционным решением.
