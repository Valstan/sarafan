На аккаунте Cloudflare владельца — **два** воркера, а не один. Второй, `karman-tg`
(задеплоен 2026-06-13, 422 байта, **привязок ноль**), — прозрачный сквозной прокси:
берёт путь, query, метод, заголовки и тело запроса и переправляет всё это в
`api.telegram.org`. **Не проверяется ничего** — ни секрет в заголовке (у нашего
`tg-relay` он есть), ни метод, ни маршрут, ни хост.

**Что это значит.** Кто угодно, узнав адрес, гонит через аккаунт владельца произвольные
вызовы Bot API со своим токеном: бесплатный анонимизатор происхождения запросов плюс
расход чужой квоты. Своих секретов воркер не отдаёт — их у него нет, — поэтому это не
утечка, а открытая дверь.

**Отдельно, и это важнее для соседей:** токен звонящего едет в такой схеме **в URL**, то
есть попадает в журналы и аналитику владельца аккаунта. Если MatricaRMZ ходит в Bot API
через него — их токен транзитом проходит через аккаунт, который им не принадлежит. «Не
лежит» и «не проходит» — разные утверждения; они спрашивали только первое.

**SETKA им не пользуется — проверено, а не предположено:** строки `karman-tg` в
репозитории нет ни одной, `TG_PREVIEW_RELAY_URL` указывает на `tg-relay`, а все отправки
в Telegram бьют в `api.telegram.org` литералом — настраиваемой базы Bot API в коде нет
вообще (греп по `config/` и `modules/telegram_http.py`).

**Не трогаем сами:** аккаунт владельца, имя проекта чужое, удаление чужого рабочего
инструмента без спроса — ровно та операция, чья видимая область у́же фактической.
Починка, если воркер ещё нужен: тот же `X-Relay-Secret`, что у нашего релея, — правка в
четыре строки. Отчёт ушёл письмом
