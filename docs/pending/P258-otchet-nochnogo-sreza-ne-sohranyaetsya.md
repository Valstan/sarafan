# P258 — Отчёт ночного среза не сохраняется: доказательства приёмки теряются

**Приоритет:** 🟡 техдолг (критерий приёмки нельзя проверить после рестарта)
**Открыто:** 2026-11-27 · `⏱ 2026-11-27 · snooze 0 · fresh`

## Симптом

Отчёт ночного среза discovery (`tokens_measured`, `communities_categorized`,
`engines`, `regions_checked`) живёт **только в логе воркера**. Второе место, где он
формально есть — результат задачи celery, но он истекает через час
(`result_expires = 3600` в `config/celery_config.py`). Лог воркера при этом
**обнуляется на каждом рестарте юнита** (P257: `Start-Process -RedirectStandardError`
создаёт файл заново).

Замер 27.11 (эта запись): срез 04:00 отработал целиком — **33 вызова discovery, 0
отказов**, движок MiniMax (журнал `logs/minimax_usage.jsonl`). Отчёт задачи в это
момент был проверен (04:12) и содержал `tokens_measured: True`,
`communities_categorized ≥ 19` по каждому из 6 регионов. **В 07:43 воркеры
перезапустили** (выкатка PR #1313) — и лог с отчётом исчез. Восстановить поля отчёта
теперь нечем: в журнале расхода есть только факт вызова, а не результат задачи.

## Чем это грозит

Строка будильника на 28.11 (срез ночи 27.11→28.11) требует проверить п. 5 —
«срез discovery 04:00: метка `discovery`, `tokens_measured: True`, 0 неуспешных».
Две из трёх частей проверяются по журналу (`logs/minimax_usage.jsonl` он
**не** обнуляется). Третья — `tokens_measured` — после рестарта недоступна: её
негде взять. Формально гейт закрыть нечем, и он закрывается «на глаз» — а это ровно
тот класс, который канон называет «провал замера».

Второй удар — тот же, что и в P257, но по данным приёмки: рестарт юнита стирает
не «шум», а **доказательства**.

## Что уже сделано 27.11

**Частично закрыто скриптом среза** [`scripts/stand_night_cut.py`](../../scripts/stand_night_cut.py):
он **снимает снимок логов воркеров** (`logs/night_cut_<метка>/`) до разбора и
пишет JSON-отчёт рядом. То есть то, что в логе уже есть, после рестарта выживает.

## Что делать

1. **Сохранять отчёт задачи там, где он переживёт рестарт.** Варианты:
   - строка в БД (таблица прогонов discovery/recheck: метка, окно, `engines`,
     `tokens_measured`, `communities_categorized`) — тогда отчёт читается мимо логов
     вообще;
   - или JSON-файл на диске (`logs/reports/<задача>-<метка>.json`) — дешевле, но
     разбирать его потом руками.
2. **Перевести критерий приёмки на сохраняемый источник.** Скрипт среза должен
   читать отчёт задачи, а не лог; лог — только для диагностики.
3. **Отдельно — про рестарт.** Пока логи обнуляются на рестарте (P257), любой
   рестарт юнита между 04:00 и чтением отчёта уничтожает данные. Пункт 1 делает
   это неважным, пункт 3 — отдельная задача.
