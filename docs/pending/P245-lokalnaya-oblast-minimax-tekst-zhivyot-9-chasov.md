# P245 — Локальная область движка MiniMax: вход живёт ~9 часов

**Приоритет:** 🟡 техдолг (работает, но с ограничением по времени)
**Открыто:** 2026-11-26 · `⏱ 2026-11-26 · snooze 0 · fresh`

## Симптом

Локальная рабочая область движка MiniMax Code
(`infra/windows/setup_minimax_area.py`, каталог `minimax-accounts` в профиле
пользователя) работает, пока жив access-токен. Живёт он ≈ 9 часов (замерено
26.11: `expiresAtMs` профиля — ~11,9 ч на момент замера). После истечения
движок перестаёт видеть вход и отвечает «нет аккаунта» / «нет входа»:
локальная машина снова не может ни классифицировать посты, ни выполнять
задания агентов.

**Проверка (одна команда):**

```powershell
.\venv\Scripts\python.exe infra\windows\setup_minimax_area.py --check
```

## Что показала граница 26.11 17:03

Access-токен области `work` (аккаунт `45@id45d.myjino.ru`, karman_id=58) истёк
**26.11 17:03:58 МСК** — и **продлился сам**, без всякой ручной правки:

- в 17:03:34 движок обновил вход: **поколение сессии 1 → 2**, новый срок —
  **27.11 05:03:37 МСК** (11 ч 56 мин);
- состояние сессии CLI — `authenticated`, расход за сутки: 361 вызов, 357
  успешных, отказы — `engine_failed` 1, `quota_exhausted` 1, `auth_expired` 1,
  `cli_slot_busy` 1;
- ночной волне 22:00 и срезу discovery 04:00 вход обеспечен.

**Остаточный риск тот же:** журнал воркера счётчик «продлений входа» **не
отметил** (0), то есть путь продления в журнале не различим — «продление у
Кармана» или «следующий аккаунт». Пока это работает — не трогать; если область
останется без входа, волны уйдут в **платную страховку** (DeepSeek API).

Проверка перед ночью: `.\venv\Scripts\python.exe scripts\minimax_renew_check.py`
→ строки «срок», «состояние сессии CLI», «поколение сессии».

## Почему refresh-токен не переносится

Обмен refresh-токена на сервере **ротирует** его. Живой профиль MiniMax Code
принадлежит работающей сессии владельца: перенеся, обмен обесценил бы
refresh-токен в живом профиле, и сессия владельца лишилась бы возможности
продлить вход. Поэтому в рабочую область кладётся штатная заглушка проекта
(`modules.minimax_engine.REFRESH_PLACEHOLDER`): access-токен работает как
обычно, а его продление честно провалится.

## Что делать, когда вход истёк

1. **Перезавести область** — если на машине есть свежий вход MiniMax Code:

   ```powershell
   .\venv\Scripts\python.exe infra\windows\setup_minimax_area.py
   ```

   Скрипт берёт access-токен и срок его жизни из профиля MiniMax Code на
   машине и кладёт их в область штатной функцией
   (`modules.minimax_engine.write_access_token`).

2. **Прийти арендой у Кармана** — тогда область заводится сама
   (`materialize_leased_profile`), и доступ настоящий refresh-токен.

3. **Решение владельца про перенос настоящего refresh-токена** — тогда живой
   профиль и локальная область должны указывать на **один и тот же** вход
   (иначе refresh-токен снова разойдётся). Отдельная задача, не правится
   молча.
