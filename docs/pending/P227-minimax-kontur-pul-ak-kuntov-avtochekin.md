# P227 — Контур MiniMax: движок с пулом аккаунтов и авто-чекином

> Запись `P227` реестра [PENDING_FOLLOWUPS](../PENDING_FOLLOWUPS.md). Индекс грепается, запись читается целиком, реестр целиком не читается никогда ([D-097](../../AGENTS.md)).

`⏱ 2026-11-13 · snooze 0 · fresh · **движок готов и проверен живьём** (13.11): очки чекина берутся автоматом (`signin/claim` → `claim_result=1, points=400`), модель отвечает через `mcode exec` (`MiniMax-M3.1-Flash`, 1,7 с); ждём HTTP-API Кармана на общий учёт и решение владельца — бокс или ПК`

## Что сделано 13.11

- **Разобрана вся система** (пионер — KARMAN: `karman/docs/minimax.md`,
  `lib/accounts/*`): пул аккаунтов, журнал активаций с уникальным индексом
  `(account_id, used_on)`, окно активации 24 ч, номер клетки = серия дней
  подряд, очки 400/1000/4000 (живут 30 дней), ротация «по деньгам».
- **Проверено живым токеном**, а не по документации: панель чекина отдаёт
  7 клеток (`day_no`, `status`, `points`, `is_today`); `claim` начислил очки;
  повтор за те же сутки вернул «уже получено»; `mcode exec` без TUI ответил
  моделью; протухший access-токен CLI обновляет сам (refresh-токеном).
- **Движок `minimax`** (`modules/minimax_engine.py`, ADR-0017): пул профилей
  MiniMax Code, авто-чекин, ротация по правилу Кармана, строгий JSON-ответ
  через `--output-schema`, отказ пула отделён от поломки движка
  (`accounts_exhausted`, а не `quota_exhausted`).
- **Переключатель общий** (`CLASSIFIER_ENGINE=minimax`) — тот же, что у
  free-тира Опенкода; откат — одна env.

## Находки, которые меняют картину

- **Публичный API MiniMax с ключом аккаунта не годится:** 401 («нужен API
  secret key») и 2062 `no active token plan subscription` — очки чекина
  тратятся на сценарии MiniMax Code, а не на API. Единственный путь
  автоматизации — рантайм Code.
- **С бокса MiniMax не отвечал — и это был IPv6:** DNS отдаёт AAAA первыми,
  IPv6-маршрута на боксе нет, curl вис до таймаута. По IPv4 — 200 за 0,54 с.
  Лечится `--dns-result-order=ipv4first` для Node и обычным откатом на IPv4
  для Python.
- **Программного логина по паролю нет** — только OAuth device-flow. Каждый
  новый аккаунт в пуле = один вход владельца в браузере.

## Что показала проверка на проде 13.11

- **Поставлено на бокс:** MiniMax Code CLI (0.7.7 установщик + 0.7.4 npm) и пул
  из двух профилей в `/home/valstan/minimax-accounts` (0700/0600, владелец —
  `valstan`).
- **DNS оказался главным препятствием:** резолверы VPS отдают для
  `*.minimax.io` адреса, до которых соединение не устанавливается (таймаут 12 с);
  `1.1.1.1` отдаёт другие, до них соединение идёт за 0,02 с. Лечится пином
  рабочих адресов в `/etc/hosts` (`scripts/minimax_dns_pin.py`) + таймер
  `minimax-dns-pin.timer` на боксе (раз в час: адреса ротируются).
- **Авто-чекин и ротация на проде работают:** панель читается с бокса, движок
  сам обновляет протухший access-токен; ячейка «уже забрано» → повторного
  начисления нет; порядок ротации по правилу Кармана — acc5 → acc1 (у acc5
  ближайшая активация даёт 1000 очков, у acc1 — 400).
- **Не работает на боксе вызов модели:** вендорский CLI не признаёт скопированный
  профиль («Sign in to MiniMax»), хотя токен живой. Причина — привязка записи
  токена к установке CLI. Нужен **вход владельца в каждом аккаунт на боксе**
  (device-flow, ~2 минуты). На ПК тот же движок вердикт даёт верный ✓.
- **acc1** без входа неживой: его refresh-токен отклонён (HTTP 400).

## Что осталось

1. **Вход владельца в аккаунты на боксе** — по одному device-flow на аккаунт
   (~2 минуты в браузере): без него CLI на боксе не признаёт скопированный
   профиль.
2. **HTTP-API Кармана на учёт активаций** (`GET /accounts/available`,
   `POST /activations`, идемпотентно по `(account_id, used_on)`) — без него
   общей статистики нет, а значит один аккаунт достанется и Сарафану, и
   владельцу в одни сутки. Письмо мозгу от 13.11 приложено.
3. **Решение владельца: где крутить рантайм.** Бокс: 597 МБ available, swap
   нет, `mcode exec` — Node-рантайм (пик 381 МБ по всем node-процессам), а
   воркер уже убивался по OOM (P164). ПК владельца: мост Pull, как у free-тира
   Опенкода, — но контур живёт, пока включён ПК.
4. **Цена одной классификации в очках** — замер на живом аккаунте: от этого
   зависит, сколько аккаунтов нужно на нашу волну.
5. **Сколько аккаунтов отдаём Сарафану** (владелец).
