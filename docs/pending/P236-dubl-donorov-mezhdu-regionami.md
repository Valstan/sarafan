# 🟡 Дубли доноров между регионами: 71 VK-группа заведена в нескольких районах сразу

> Запись `P236` реестра [PENDING_FOLLOWUPS](../PENDING_FOLLOWUPS.md). Индекс грепается,
> запись читается целиком, реестр целиком не читается никогда ([D-097](../../AGENTS.md)).

`⏱ 2026-11-23 · snooze 0 · fresh · найдено при разборе «сменили категорию» (P235):
71 группа заведена в нескольких регионах (187 регистраций, 116 лишних); 35 групп
делят все три закамских района (клон-пул P204), 5 групп заведены дважды в одном
регионе, в проде есть регион `test`; **общие группы не отключены** — посты одной
группы идут в ленты нескольких районов`

## Что это

Одна и та же VK-группа может быть заведена в `communities` для нескольких регионов.
Донор один, а посты его собираются в ленты **нескольких** районов — то есть один
и тот же чужой пост приходит читателям разных районов.

## Почему это не «второй клон-пул», а общий хвост

P204 чистил клон-пул **Закамья** (20.10) — и вылечил его в трёх районах по
собственным (не чужим) донорам. Но **сами общие группы остались**: 35 из них до сих
пор числятся сразу в трёх районах. То есть чистка убрала «своих», а «общих»
оставила — и они по-прежнему кормят три ленты вместо одной.

Плюс хвост шире Закамья: 30 групп делят два региона, 5 — три и больше.

## Что с этим делать (решение — за владельцем)

1. **Снять лишние регистрации** — по одной группе оставляем в том регионе, где
   она и правда своя. Для 35 закамских это готовый список из P204.
2. **Разбирать «дважды в одном регионе»** (5 групп) — это дубль строки, чинится
   точечно.
3. **Регион `test` в проде** — либо удалить, либо пометить неактивным.
4. **Общий запрет на повторную регистрацию** — при заведении кандидата проверять,
   не занята ли группа уже другим регионом (в `community_candidates` есть
   `ON CONFLICT(region_id, vk_id)`, но сквозной проверки между регионами нет).

## Решение владельца 24.11: деактивировать лишние по area-guard

Заказ: «деактивировать лишние по area-guard» (плюс 5 дублей в одном регионе и
регион `test`).

- **Правило «где группа своя» — то же, что в discovery** (PR #1233, area-guard):
  у группы VK город (`city`), у города — область; область региона — по городу
  области (родитель-область) либо по городу-центру района. Регистрация, где
  область региона **не совпала** с областью группы, — лишняя.
- **Не гадаем:** если область неизвестна (ни у группы, ни у региона) — регистрация
  остаётся как есть; если своей регистрации не нашлось ни в одной области —
  группа отдаётся на разбор, а не выключается целиком. То же «не знаю» ≠ «чужая».
- **Инструмент:** [`scripts/dedupe_shared_communities.py`](../../scripts/dedupe_shared_communities.py) —
  превью (что и почему выключается), затем `--apply`. Выключение **обратимо**:
  `is_active=False` + `disabled_at` + `disabled_reason` (по образцу
  `scripts/deactivate_communities.py`), строки не удаляются. Причины: лишняя
  регистрация — `pool_shared_group`, дубль строки — `duplicate_row`, регион
  `test` — `region_test_cleanup` (не `dormant_t1_auto` — этот оживляет
  авто-recheck).
- **Наши главные группы не трогаем** — в том числе их регистрацию в своём же
  районе.
- **Остаётся за владельцем:** группы, зарегистрированные в нескольких районах
  **одной области** (список в отчёте скрипта) — area-guard различает области, а
  не районы; для 35 закамских есть готовый список из P204.

## Что сделано 24.11 (на проде)

**Выключено 26 регистраций** (обратимо: `is_active=False` + `disabled_at` +
`disabled_reason`), строки не удалены:

| Что | Сколько | Причина |
|---|---|---|
| Дубль строки в одном регионе | 6 | `duplicate_row` — оставлена строка с большей историей |
| Регион `test` (9 групп, все — копии групп Малмыжа и Пижанки) | 9 | `region_test_cleanup` |
| Общая группа в чужом районе | 11 | `pool_shared_group` |

**Что изменилось в правиле (и почему).** Сначала было «область региона против
области группы» (как в discovery, PR #1233). На проде этот вариант **не работает**
— проверено на живом API 24.11:

- `database.getCities` по конкретному `city_ids` отдаёт список важных городов
  страны (`count: 21`) и **не содержит поля `area`**; вариант с `need_all=1`
  отдаёт все 157 490 городов постранично, но фильтр по `city_ids` не применяется;
- у **80 из 84** активных регионов пуст `center_city` → область региона по VK
  не определяется.

Поэтому правило реализовано на том разрешении, которое данные дают: **город
группы** (`groups.getById fields=city`) против **города региона** (город его
главной группы — `regions.vk_group_id` есть у всех 84 активных). Это тот же
географический принцип, но строго finer: отличает район от района.

**Сколько решилось:** из 26 общих групп городом решаются **9** (Бугульма,
Альметьевск, Нижнекамск → убраны из региона области `tatarstan_obl`, где город
региона — Казань; Котельнич → из Даровского; Яранск → из Тужи, Санчурска и
Кикнура; Арск → из Высокой Горы и Тюлячей; Подосиновец → из Опарино;
Альметьевск → из Уруссы). **17 осталось нетронутыми:** их город не совпал ни с
одним городом региона — это деревни и областной центр («Казань», «Буинск»,
«Старый Буртек»…), то есть «нигде не своя», а не «лишняя регистрация». Их
смотрят глазами.
