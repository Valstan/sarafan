# Движок классификатора через харнесс OpenCode на том же VPS

## Контекст

DeepSeek-контур мёртв с 22.09.2026 (http_402, P177): сеть публикует без
нейро-фильтра ~3 недели, ручной прогон `/progon` стоит часов оператора.
Пополнение баланса — ход владельца, который не сделан. Альтернативный шлюз
(OpenCode Zen) предоставляет бесплатные модели без аккаунта, ключ
(`OPENCODE_API_KEY`) бесплатного тира работает.

Задача владельца (14.10): поставить харнесс OpenCode на прод-VPS и вернуть
им нейро-фильтрацию волн парсинга: вердикты publish/delete/hold, сомнительные
отдельно на приёмку владельцем в панели `/classifier`, правки → сырьё для
дистилляции правил.

Замеры с бокса 14.10 (VPS в EU):

- установка CLI: npm/installer доступны, binary 1.19.0 работает;
- `opencode run` (CLI headless) стабильно висит после `init` (~170 c, ноль
  байт вывода) — непригоден для автоматики;
- `opencode serve` (headless server, 127.0.0.1) поднимается и отвечает;
- прямой API шлюза без ключа молчит; **free-tier работает только «from within
  OpenCode»** (FreeTierError на прямом POST);
- **muse-spark-1.3-contributor-free: 403 RegionError** — geo-блок IP бокса
  (как и предупреждал владелец: «только через VPN»);
- живые free-модели с бокса: longcat-2.5-preview-free (1M ctx),
  space-bunny-free (1M ctx), mimo-v2.6-flash-free (200k ctx); zero-retention;
- бокс — контейнер OpenVZ (P163): tun недоступен, WireGuard/OpenVPN внутри
  не поднимаются; туннелирование возможно только userspace-уровнем (ssh -D /
  GOST / прокси).

## Решение

1. **`opencode serve` как systemd-юнит `setka-opencode.service`** на боксе,
   слушает 127.0.0.1, ключ и basic-auth — в env-файле на боксе (600, вне
   репо). CLI (`run`) не используем — он на этом боксе не работает.

2. **Движок-переключатель `CLASSIFIER_ENGINE`** (deepseek | opencode, дефолт
   deepseek). Точка переключения одна — `modules/classifier/headless.py::chat`
   (роутер); DeepSeek остаётся дефолтом, откат пилота — одна env-переменная
   без деплоя кода. Контракт ответа движка зеркалит `deepseek_client.chat`,
   поэтому вызывающий код (`classify_chunk` → `classify_posts` → таска /
   prepublish / кнопка UI) не различает движки.

3. **Цепочка моделей с авто-фолбэком** (`OPENCODE_MODEL_CHAIN`, дефолт:
   muse → longcat → space-bunny → mimo). Free-tier ротирует модели (владелец
   14.10): первая ответившая закрывает вызов. Muse физически стоит первой:
   когда бокс получит нужный geo (донорский SOCKS / прокси — P195), она
   встаёт в работу сама, без правок кода.

4. **Нормализация ответа в движке**, не в классификаторе: ```json-обёртки и
   топ-level массив вердиктов (привычка longcat) приводятся к контракту
   `{"verdicts": [...]}`; счётчики serve (`input/output`) → `total_tokens`.
   Править терпимость общего парсера под привычку одного движка — версия
   расходится молча (G334-класс).

5. **Fail-open сохранён**: отказ всех моделей = `engine_all_failed` → ноль
   вердиктов → пост публикуется по обычным фильтрам (прежнее поведение).
   Приёмка сомнительных не меняется: `hold` и низкая уверенность (<60)
   видны в панели `/classifier`, правки идут `correction`'ами и питают
   `/distill`.

6. **Разовый прогон** — `scripts/opencode_classify_once.py` (dry-run по
   умолчанию, живая запись под `--write`); печатает гистограмму действий и
   список сомнительных с lip/темой/причиной.

## Альтернативы

- **Прямой HTTP к Zen-API из классификатора** — невозможно: free-tier
  требует «from within OpenCode»; платный тариф требует оплаченного аккаунта
  (ход владельца).
- **OpenRouter** (egress 200) — возможен как замена, но меняет модель и
  провайдера; Muse там представлена иначе. Оставлено как план Б.
- **Донар-VPS + ssh -D SOCKS под Muse** — работает в OpenVZ; отложено до
  решения владельца о покупке (~200–400 ₽/мес), см. P195. Цепочка фолбэков
  убирает блокировку: прод не ждёт этого решения.
- **Платный прокси** — тот же эффект быстрее, но третья сторона видит текст
  постов; отклонено как постоянное решение.

## Последствия

- Нейро-фильтр возвращён без оплаты DeepSeek и без машины владельца; при
  нестабильности бесплатного тарифа деградация управляемая (цепочка +
  fail-open), а не «сеть публикует что попало».
- Ротация бесплатных моделей теперь ожидаема, а не инцидент: замер
  (`opencode models` + пробный вызов) — обновляет `DEFAULT_MODEL_CHAIN`.
- Секрет `OPENCODE_API_KEY` живёт на боксе в env-файле 600 + `auth.json`
  сервиса; в репо не попадает (gitleaks-staged + CI secret scan).
- Muse остаётся целью №1 цепочки: при появлении туннеля меняется одна
  переменная окружения (или ничего, порядок уже написан).
