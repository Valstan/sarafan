# Единый v2-сервер OpenCode — фильтрация постов и кодинг владельца на одном serve

## Контекст

ADR-0007 поднял на боксе `opencode serve` v1.19 отдельным юнитом
(`setka-opencode.service`) — только под движок классификатора. Параллельно
владелец кодит OpenCode'ом на нескольких машинах (опыт GONBA: web-UI сервера
на боксе + туннель и pair-ссылка), и 17.10 поставил задачу: **не плодить
серверы — самая новая версия пусть работает и на фильтрацию постов, и для
кодинга**.

Что показали пробы 17–18.10 на установленном v2.0.32:

- контракт сменился радикально: вместо json-lines одного POST — сессии и
  сообщения (`/api/session`, `prompt` → `wait` → `message`), и модель —
  свойство сессии, а не сообщения;
- free-tier тот же («from within OpenCode»), ключ не нужен; **аккаунт-ключ
  бесплатный тир не поднимает** — открывает только платные модели;
- **инструменты моделей стали опаснее**: без запретов модель по просьбе из
  текста поста реально исполняет shell (маркер в `$HOME` создан, exit 0).
  Текст постов — недоверенный вход, писать его в сессию с инструментами
  значит дать посторонним исполнителя на боксе;
- запрет `read` на `*` ломает сам вызов free-tier (`provider.auth`
  «free tier can only be used from within OpenCode»), зато узкие
  read-запреты работают и вызов не ломают;
- сессии копятся: без уборки каждая волна оставляет десятки сессий в данных
  сервера;
- 18.10 контур собран и выкачен (#910), но живой прогон упёрся в
  **платформенный IP-гейт free-tier**: 403 `FreeTierError` на все модели
  цепочки и любые наборы пермишенов — инцидент вендора ~16–17.10 (P201),
  не наш payload. Переключение движка отложено по решению владельца.

## Решение

1. **Один сервер.** `opencode-web.service` (v2.0.32, 127.0.0.1:49374,
   `Restart=on-failure`, всегда включён) — веб-кабинет владельца и движок
   фильтрации. v1-контур выведен из эксплуатации: `setka-opencode.service` и
   `setka-opencode-run.service` погашены и disabled; бинарь v1.19 убран в
   `~/.opencode/bin/opencode.v1.19.bak` (точка отката на время обкатки), рядом
   единственная установка v2 — `~/.opencode/bin/opencode`.
2. **Движок только прикрепляется.** `OPENCODE_NO_SPAWN=1`: свой serve движок
   не поднимает (второй инстанс дрался бы с systemd за порт); сервис молчит —
   короткая фора на рестарт (30 с) и тихий отказ волны (fail-open).
3. **Запреты инструментов — на уровне сессии.** `CLASSIFY_SESSION_PERMISSIONS`:
   deny `shell/edit/webfetch/websearch/subagent/browser/grep/glob/todowrite/
   skill/question/execute` плюс узкие read-запреты (`*anon.env*`, `*/.ssh/*`).
   Каждый проверен живьём; `read` на `*` в списке нет — он ломает free-tier.
4. **Сессии убираются за собой** (DELETE после ответа).
5. **Откат** — одна env-переменная `CLASSIFIER_ENGINE=deepseek` (без деплоя
   кода), как и было в ADR-0007.

## Альтернативы

- **Два сервера: v1 под движок + v2 под кодинг** — отклонено владельцем
  17.10 («не будем плодить несколько серверов опенкоде»).
- **Оставить движком v1** — протокол v1 тупиковый, апдейтов нет.
- **Прямой API Zen** — невозможен: free-tier только «from within OpenCode»
  (см. ADR-0007).

## Последствия

- Serve — общая точка отказа кодинга и фильтрации: его падение останавливает
  оба (митигации: `Restart=on-failure`, фора + тихий отказ движка, откат
  `CLASSIFIER_ENGINE=deepseek`). Разделять обратно — только по решению
  владельца.
- Пароль сервера живёт в двух env-файлах на боксе (serve и клиент-движок) —
  копия файл-в-файл, в репо не попадает.
- Утечка `/tmp`-мусора (P200) устранена конструктивно: serve теперь
  поднимается per-restart, а не per-chunk; чужие запуски подчищает свипер из
  PR #903. Замер после выката 18.10: `.bcdf*` = 0.
- **Бесплатный тир — внешняя зависимость под политикой вендора.** 17–18.10
  free-tier платформы закрылся по репутации IP (не по нашему payload):
  контур, целиком построенный на нём, можно выключить волной без
  предупреждения. Страховка для прод-конвейера — платный ключ или свой выход;
  решение отложено (P201), `CLASSIFIER_ENGINE` остаётся `deepseek`.
- Обновление v2 меняет контракт молча: версия — точка интеграции; после
  апдейта прогонять `scripts/opencode_classify_once.py --dry-run`.
