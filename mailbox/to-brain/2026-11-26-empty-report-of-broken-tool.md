# «Результата нет» ≠ «данных нет»: сломанный инструмент выглядит как отсутствие данных

**Контекст.** Переносили боевой контур на локальную Windows-машину (промт
КАРМАНА #161, проект SARAFAN). Пункт приёмки: «один и тот же набор постов
классифицируется локально и прод-движком одинаково — сравнение вердиктов
построчно». Инструмент сверки был готов с прошлой сессии, прогон — нет.

**Симптом.** Первый прогон: 40 постов взято, **0 совпало, 0 расходится,
«без локального вердикта: 40»**. Отказов движка — ноль, проблем разбора —
ноль. То есть отчёт выглядит как «движка нет, данных нет, сверять нечем».

**Что было на самом деле.** Движок отвечал, модель отдавала вердикты по каждому
посту. Сломан был **инструмент**: он строил карту «локальный вердикт по посту»
из JSON решения, а `lip` (ключ поста) в этой сериализации **нет** — там только
`theme`, `action`, `merge_with`, `split`, `confidence`, `reasoning`, `urgent`.
Ключ пустой → все 40 вердиктов легли в одну запись `""` → ни один пост не
нашёлся. Единственный способ это увидеть — **сравнить сырой ответ модели с
отчётом**, а не поверить отчёту.

**Почему это дорого.** Ошибка прожила месяц в репозитории и ни разу не
покрасила гейт: инструмент честно печатал «результата нет», и это читалось как
«данных нет» — то есть как отсутствие данных, а не как поломка. Слово
«нет» в отчёте не различает эти вещи.

**Правило (одна строка).** **Пустой отчёт инструмента разбирается до конца:
сначала докажи, что инструмент способен найти результат вообще, и только
потом говори «данных нет».** Иначе сломанный инструмент годами выглядит как
отсутствие данных — и его чинят не там, где он сломан.

**Что помогло найти.** Три шага, которые стоит повторять:

1. **Проверка ответа в обход инструмента.** Один вызов движка напрямую, ответ
   напечатан целиком. Ответ есть — значит, чинить инструмент, а не искать
   ключи.
2. **Ключ сущности не берётся из сериализации решения.** «Решение» и
   «идентификатор» — разные вещи: идентификатор (`lip`) живёт в объекте
   вердикта, а не в его JSON. Общее правило: если словарь «решения» не
   содержит ключа сущности — ключ бери из объекта, а не из словаря.
3. **Регресс на сам инструмент.** Шесть тестов на индекс вердиктов и на
   сравнение по полям — чтобы «инструмент не находит своё» больше нельзя
   было выдать за «данных нет».

**Переносимо.** Любой проект, где есть «сверка A против B» и отчёт может
оказаться пустым: сверка вердиктов модели, сверка выгрузок, сверка двух
списков. Класс общий: **отчёт, который умеет только говорить «нет», не
отличает «нечего сравнивать» от «нечем искать»**.

**Что переносимо из правки.** Расхождение вердиктов по полям стоит показывать
**по полям отдельно**: «решение совпало» и «уверенность совпала» — разные
вещи. Строгая сверка «совпали все поля сразу» смешивает решение (риск) и
число (шум), и из неё нельзя понять, где на самом деле разошлось.
