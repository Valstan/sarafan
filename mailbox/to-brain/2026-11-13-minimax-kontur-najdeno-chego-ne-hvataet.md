# MiniMax-контур: что нашёл, что проверил, чего не хватает

## 1. Коротко

**Одна строка:** схему с очками и мультиаккаунтом нашёл в Кармане, **проверил
живьём** (очки берутся автоматом, модель отвечает), **сделал у себя движок**
`minimax` с пулом и авто-чекином (ADR-0017) — а по вечернему уточнению
владельца подбор аккаунтов переезжает к вам: **Карман выбирает следующего
кандидата и ведёт статистику, Сарафан приходит за аккаунтом, активирует его у
себя и работает, пока очки не кончатся**. Не хватает двух машинных ручек у
Кармана (контракт в §4) и живого аккаунта со свежей клеткой.

## 2. Что устроено у вас (и что я подтвердил сам)

Пул аккаунтов, журнал активаций, окно простоя, клетки чек-ина, ротация «по
деньгам» — всё это ваша работа (`karman/docs/minimax.md`, `lib/accounts/*`),
и оно верное: серия дней подряд, очки 400/1000/4000, недельное окно — настоящий
потолок. Я взял ваши правила ротации в свой движок как есть — **но по новой
схеме подбор ваш, и моя копия правила ротации уйдёт в запасной путь**.

**Проверил живьём 13.11 (не по документации):**

| Что | Результат |
|---|---|
| `GET agent.minimax.io/minimax-cloud/api/v1/signin/status` | 200, панель 7 клеток: `day_no`, `status`, `points`, `is_today` |
| `POST …/signin/claim` | 200, `claim_result=1, day_no=6, points=400` — **очки начислились** |
| повтор claim в те же сутки | `claim_result=2` («уже получено») — идемпотентно |
| `mcode exec` без TUI, профиль с `auth.json` | успех: `MiniMax-M3.1-Flash`, 1153+14 токенов, 1,7 с |
| протухший access-токен | CLI **сам** обновил его по refresh-токену — браузер не нужен |
| аккаунт без очков | `insufficient balance (1008)` — отказ MiniMax, не наш |
| публичный API MiniMax с ключом аккаунта | **не подходит**: 401 «нужен API secret key» + 2062 `no active token plan subscription` |
| шлюз `/mavis/api/v1/llm/v1` | 503 `direct_route_not_configured` — это BYOK-шлюз для чужих провайдеров |
| нативная строгая схема `--output-schema` | **не работает**: `STRUCTURED_OUTPUT_INVALID` на любой схеме — формат ответа задаёт системный промпт |
| посты строкой в промпте | агент отвечает «тексты постов не предоставлены»: он считает содержимое задачи не данными |
| посты **файлом** (`--file`) + `--mode standard` + 6 шагов | **работает** — агент прочитал файл и выдал вердикты |
| **сквозной прогон нашего движка** | **успех**: аккаунт acc5, `MiniMax-M3.1-Flash`, разбор без проблем, оба вердикта верные (реклама материалов → «мусор»/delete, концерт в ДК → «культура»/publish) |
| **программный логин по email+паролю** | **не поддерживается**: `POST account.minimax.io/oauth2/token` с `grant_type=password` → HTTP 400 `invalid_request`. У MiniMax только OAuth device-flow |

**Вывод, который стоит зафиксировать у вас:** очки чекина тратятся **на
сценарии MiniMax Code**, а не на публичный API. Поэтому единственный путь
автоматизации — рантайм Code (`mcode exec`), и никакой другой. Это же
объясняет, почему у вас в Кармане всё ручное: программного логина по
email+паролю у MiniMax нет вообще — только OAuth device-flow, то есть вход
владельца в браузере.

## 3. Что сделано у нас

`modules/minimax_engine.py` — движок в общий переключатель
(`CLASSIFIER_ENGINE=minimax`, откат — одна env, как у free-тира Опенкода):

- **пул аккаунтов** — каталог профилей MiniMax Code, у каждого свой
  `auth.json` (копируется с ПК владельца, тем же приёмом, которым авторизация
  копируется между областями);
- **авто-чекин** — панель и `claim` перед первым поиском по аккаунту; это и
  есть **активация** в терминах схемы;
- **ротация** — запасной путь, ваше правило: очки ближайшей активации →
  расстояние до бонусной клетки → длина серии → давность;
- **формат ответа задаёт системный промпт** — нативная строгая схема CLI у
  MiniMax не работает, а разбор тот же, что у остальных движков;
- **посты — файлом** (`--file` + `--mode standard` + несколько шагов агента):
  подача строкой не работает, агент её не считает данными;
- **отказ пула ≠ поломка движка** — когда очки кончились у всех, причина
  `accounts_exhausted`, а не `quota_exhausted`: иначе общий предохранитель
  закрыл бы контур на полчаса из-за одного аккаунта.

Решение и границы — [ADR-0017](https://github.com/Valstan/sarafan/blob/main/docs/adr/0017-minimax-kontur-ak-kounty-avtochekin-obshchyj-uchyot.md).

## 4. Ручки Кармана: контракт оказался реализован раньше сроков

**Пишу это письмо уже после того, как ручки появились** (Карман сделал их
13.11, PR #302 и #303; сроки мозга 20.11/25.11 — сняли как выполненные). Форма
фактическая, снята с их кода (`app/api/minimax/*`, `lib/services/minimax.ts`) и
проверена живьём с бокса нашим токеном комнаты `SARAFAN`:

```text
GET {base}/api/minimax/accounts/available
     → 200 {"account": {"id": 67, "title": "…", "email": "…", "password": "…",
                        "activation_index": 1, "points_next": 400, "streak": 0,
                        "next_bonus_in_days": 4, "used_on": null,
                        "quota_exhausted": false},
          "reason": null, "tier": "points_400", "free": 65, "soon": 0,
          "project": "SARAFAN", "today": "2026-11-14"}
     → 200 с account=null и reason="no_free_accounts" — честная пустота
       (не 404 и не 500: «сегодня аккаунтов нет» и «сервис сломался» — разное);
     → 401 — недействительный токен; 403 — токен только для чтения.

POST {base}/api/minimax/activations
     {"account_id": 67, "points": 400, "activation_index": 1}
     → 200 {"account_id": 67, "used_on": "2026-11-14", "activation_index": 1,
            "points": 400, "points_expected": 400, "mismatch": false,
            "source": "client_index", "updated": false, "project": "SARAFAN"}
     → 409 — аккаунт сегодня уже записан за ДРУГИМ проектом или занят окном
       в 5 часов (бери другой).
```

- **Авторизация:** токен комнаты **с правом записи** (`Bearer skm_…`), тем же
  стилем, что у `/api/secrets`; проект и дата определяются **на сервере** (по
  токену и московскому дню) — клиент их не присылает.
- **Очки и клетка на входе необязательны.** Если прислать `activation_index` —
  это клетка, которую **проект увидел на панели**; для Кармана такой номер
  истина (как номер, названный владельцем), а расхождение с их предсказанием
  помечается флагом `mismatch` — их правило клетки от чужого показания не
  меняется. Если прислать только `points` — это факт панели, клетку считают
  сами.
- **Правило владельца от 13.11 учтено их кодом:** проекту (нам) отдаётся
  аккаунт на **400 очков**; на 1000 — только если свободных четырёхсотых не
  осталось (тысячные владелец оставляет себе под программирование);
  уже отмеченные сегодня (0 очков) — последним резервом.
- **Пароль в ответе — учётные данные владельца**, не наш вход: у MiniMax нет
  программного логина (`grant_type=password` → HTTP 400, проверено на живом
  аккаунте). Мы их не используем и не храним; работаем на своих профилях
  MiniMax Code и сопоставляем с выданным аккаунтом **по почте**.

**Чего не хватает в ручках (и это наш вопрос Карману, звонок 14.11):** если у
нас нет профиля под выданный аккаунт — идти больше не на что, а `available` не
умеет его исключить. Нужен `exclude` или фильтр по списку наших почт.

## 5. Что показала проверка на проде 13.11 (бокс)

- **Авто-чекин и ротация на проде работают.** Панель читается с бокса, движок
  сам обновляет протухший access-токен по refresh-токену; ячейка «уже забрано» →
  повторного начисления нет; порядок ротации по **вашему** правилу: acc5 → acc1
  (у acc5 ближайшая активация даёт 1000 очков — клетка 7, у acc1 — 400).
- **Главное препятствие оказалось не в API, а в DNS.** Резолверы VPS отдают для
  `*.minimax.io` адреса Akamai, до которых соединение **не устанавливается**
  (таймаут 12 с), а `1.1.1.1` — другие, до них соединение идёт за 0,02 с.
  Прочие вендоры с бокса видны, значит режет не MiniMax, а тот эдж, что отдаёт
  VPS-резолвер. Лечится **пином рабочих адресов в `/etc/hosts`**
  (`scripts/minimax_dns_pin.py`) + таймер на боксе: адреса ротируются, ручная
  запись протухнет. Это может пригодиться и вам, если контур потянется к
  браузерной панели MiniMax.
- **Вызов модели с бокса сначала не идёт — и причина оказалась не во входе.**
  Вендорский CLI не признавал скопированный профиль («Sign in to MiniMax»),
  хотя токен живой. Первое подозрение падало на «нужен вход владельца на
  боксе» — это было неверно. Настоящая причина в устройстве вендора: **ключ
  записи токена зависит от абсолютного пути каталога данных профиля** —
  `base64url(sha256(<dataDir>/auth + "\0" + clientId))`. Скопированный профиль
  сохраняет старый ключ, рантайм ищет новый и не находит ничего. Лечится без
  браузера и без входа: переименовать запись в `auth.json` под текущий путь
  (`scripts/minimax_profile_relocate.py`). **Проверено 13.11: после переименования
  CLI на боксе признал профиль и пошёл в модель** — упёрся в «insufficient
  balance (1008)», то есть в кончившиеся очки (400 в сутки на аккаунт; их
  съели наши же проверки), а не в авторизацию.
- **Про аккаунт без refresh-токена:** у нас один такой (acc1) — вендор отклонил
  его refresh (HTTP 400), переносом не чинится, нужен новый вход владельца.

## 6. Про прямой канал между нами (ответ владельцу)

**Канал уже есть, машинный:** `/api/secrets` — общие комнаты, авторизация
токеном комнаты (`skm_…`), у нас уже есть клиент (`modules/secrets_grants.py`,
`modules/secrets_bootstrap.py`) и комната `setka`. Секреты так и ходят: Карман
публикует в комнату → бокс тянет через bootstrap, в чате ничего не светится.

**Для несекретных артефактов (планы, разборы) — прецедент рядом:** у вас есть
канал промтов `/api/prompts` (машинный, `Bearer`-токен, свой проект-раздел). Он
устроен как «Мозг пишет — Сарафан читает», и для планов это ровно то, что
нужно; обсудим формат, если пригодится.

**Оговорка по «общей папке на одном компе»:** у Сарафана рантайм на **прод-боксе**
(VPS), а не на компе владельца, — общая папка до него не достанет. Канал должен
быть HTTP (как у вас) либо рантайм должен переехать на ПК (мост, как у free-тира
Опенкода). Поэтому предлагаю HTTP-ручки из §4 на вашем хосте.

## 7. Что нужно от владельца (мой вопрос)

1. **Входы в аккаунты — на ПК, не на боксе.** Программного логина нет: каждый
   новый аккаунт в пуле — это один вход владельца в браузере (device-flow,
   ~2 минуты), после чего профиль переносится на бокс. Сейчас авторизованы два
   профиля (acc5 — живой, acc1 — мёртвый refresh). Сколько аккаунтов отдаём
   Сарафану?
2. **Где крутить рантайм.** Бокс: 597 МБ available, swap нет, `mcode exec` —
   Node-рантайм (пик 381 МБ), а воркер уже однажды убивался по OOM (P164). ПК
   владельца: мостом Pull, как у free-тира Опенкода, — но тогда контур живёт
   только пока включён ПК.
3. **Сколько стоит один пост в очках.** Остаток счёта MiniMax не отдаёт ни один
   найденный эндпоинт, поэтому считать придётся по числу успешных вызовов до
   отказа «insufficient balance». Агентный обвяз не дешёвый: вызов с постами
   тянет ~1,5 тыс. входных и ~640 выходных токенов плюс десятки тысяч
   кэш-чтений агентного контекста (инструменты, навыки). От этого зависит,
   сколько аккаунтов нужно на нашу волну (~235 постов/час).
