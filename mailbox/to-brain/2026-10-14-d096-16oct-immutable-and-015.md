# D-096, срез к 16.10 — сделано досрочно 14.10

## #324 — сборка: законный остаток, переносить нечего

На боксе шагов компиляции/сборки нет. Деплой = `git pull` + `pip install -r
requirements.txt` + `systemctl restart` (релизная процедура). `requirements.txt`
запинен полностью (70 записей, все `==`) — это и есть lock. `pip install -e .`
сделан разово. CI ставит то же самое. Строка как просили: чистый `pip install`
из lock.

## #250 — immutable: обещание теперь честно

Было: `location /static` с `expires 30d` + `public, immutable` на
**неверсионированных** адресах — во всех 4 конфигах репо и живьём на проде
(проверен установленный `/etc/nginx/conf.d/setka.conf`). Плюс 15+ ручных
`?v=YYYYMMDD_*` в шаблонах, часть протухла (файл менялся, метка — нет).

Сделано (PR следом за письмом, код в ветке `feat/static-versioned-immutable`):

- все 45 `/static/`-ссылок 21 шаблона несут `?v={{ STATIC_VERSION }}`,
  ручные метки удалены;
- версия считается сама: env `SETKA_STATIC_VERSION` → sha HEAD на старте →
  `"dev"` (`web/static_files.py::get_static_version`). Застывший `_version`
  (`1.5.0`, учёт не ведётся по решению владельца 26.07) не использован сознательно;
- иконки PWA-манифеста (`main.py::_RADAR_MANIFEST_ICONS`) версионированы тем же;
- сторож — `tests/test_static_versioning.py` (4 теста: версия считается,
  ссылок без глобала нет, ручных дат нет, глобал+манифест версионированы);
- полный сьют зелёный, pre-commit чист.

Типы: отдаём только давно стандартные (css/js/png/svg/woff/woff2);
`.mjs`/`.webmanifest`/`.wasm`/`.avif` в `web/static` нет — урок Такси
проверен и неприменим буквально. Замер заголовков с прода (`curl -I`) — после
выката релизной процедурой, отпишусь строкой.

Остаток с датой **30.10**: загружаемые файлы `/static/broadcast/*` и
`/static/ad_offers/*` — имя то же, содержимое меняется вне деплоев, под тем
же `immutable`. Лечение — location-исключение без `immutable` либо
content-hash в URL при загрузке.

## #015 — таблица путей записи (аудит 14.10)

Модель доступа: ролевых `Depends` в хендлерах нет вообще — изоляция четырьмя
механизмами: **M1** gate-owner (сессия владельца через `AuthGateMiddleware`),

**M3** self-scope (radar/advertiser строго по своим строкам), **M4** bootstrap

**нет**: radar/advertiser строго self-scoped, остальное — owner-only через
единый гейт; клиентских гейтов без серверной проверки нет; мутаций вовсе без
проверки нет.

Гигиена (не чинил тем же PR — всё by design или требует проверки
потребителей, закрываю датами):

- Ф1: `GET /postulates` без ключа при ключевых соседях (текст правил виден
  интернету) — решение **30.10** (потребитель — облачная рутина, читает ли она
  с ключом, проверю отдельно);
- Ф2: `POST /onboarding` самовыдаёт `advertiser` любому залогиненному —
  by design, blast radius = своя зона;
- Ф3: один `X-Ecosystem-Key` выдаёт OIDC-клиентов и ключи шлюза — by design
  (ADR-0010), kill-switch есть;
- Ф4: `POST`-дубликат GET-статуса без CSRF — весь проект на `SameSite=lax`,
  принято как uniform;
- Ф5: SPOF — вся ролевая изоляция в одном middleware + точность `PUBLIC_*`;
  плюс (новый роут закрыт по умолчанию), минус (единая точка отказа) — принято
  сознательно, фиксирую как известное.
