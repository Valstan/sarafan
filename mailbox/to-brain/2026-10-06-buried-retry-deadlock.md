# Похороненный повтор: `failed` без вердикта не должен выходить из отбора

За неделю простоя движка (402) встал сайт: каждый автопрогон писал строку
`failed`, а отбор исключал lip с ЛЮБОЙ строкой журнала. Повтор (`retry_failed`)
брал только строки С вердиктом. Итог — дедлок: несбывшееся нельзя ни повторить,
ни пересмотреть, волна теряется молча.

Паттерн для библиотеки (переносимый): у очереди должно быть три исхода, а не
два — «решено» (хоронить), «доставка упала, вердикт есть» (повтор без цены) и
«решение не состоялось» (вернуться с backoff + лимит попыток). У нас третьего
не было, хотя помощник, называвший такие строки «ждут движка», был — будильника
к нему не написали. Проверка на замыкание: у каждого «ждущего» состояния обязан
быть назван потребитель, который его разбудит; иначе это могила с табличкой
«зал ожидания».

Чинка у нас: PR #868 (failed-без-вердикта возвращается, пауза 1ч–7д, попыток < 5;
брошенные `selected`-сироты подбираются через сутки; решения не трогаем).
