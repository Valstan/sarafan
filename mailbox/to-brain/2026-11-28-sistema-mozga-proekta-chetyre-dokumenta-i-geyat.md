# Система мозга проекта: что переносимо

## Одна строка

Завели в Сарафане «систему мозга» (промт КАРМАНА #203, во все разделы КАРМАНА):
**конституция + линза-карта + реестр экспертов + порядок приёма промта** — и
**машинный гейт**, который ловит, что карта разошлась с кодом. Три находки
ниже — переносимые в любой проект, которому предстоит тот же промт.

## 1. Документ-карта протухает тихо — лечится гейтом, а не памятью

**Симптом.** Карта проекта (или реестр ролей) — документ, который живёт дольше
кода, который он описывает. Он **выглядит живым**, пока в нём написано «как
было»: никто не падает, тесты зелёные, а новая сессия читает карту, верит ей
и идёт в каталог, которого уже нет. Правило «обнови карту» в правилах проекта
само по себе не работает — его нечем проверить.

**Лечение.** Гейт, который проверяет **существование всех путей, названных в
документах системы**, плюс наличие обязательных разделов. Реализация — stdlib,
~150 строк, образец в проекте уже был (`scripts/pending_gate.py` — гейт
раскладки реестра PENDING).

```python
def looks_like_path(token: str) -> bool:
    if not token or not PATH_CHARS_RE.match(token):
        return False
    if token.startswith("..") or token.startswith("/"):
        return False          # вне репозитория — не наша зона
    return "/" in token or token.endswith(FILE_EXTS)
```

**Почему это переносимо.** Тот же приём ловит не только «каталог исчез», но и
«роль выпала из реестра», «маршрут приёма выкинули из документа», «правило
обновления выкинули из правил проекта». Ключевая мысль: **проверяемость правила
„обнови документ“ — это такой же гейт, как тест**. Без гейта правило держится
на памяти того, кто его писал.

**Осторожно с границами.** Проверять надо только то, что лежит **внутри**
репозитория: токены вида `..` и абсолютные пути — не наша зона (у нас в
проекте это чужие репо, куда заглядывать нельзя).

## 2. Реестр у потолка: новая строка перебивает гейт — лечится ротацией, а не удалением

**Симптом.** У нас индекс реестра техдолгов (`PENDING_FOLLOWUPS.md`) упёрся в
потолок гейта (51 200 Б). Любая новая строка — даже своя, даже правильная —
перебивала потолок и роняла гейт. Варианты «пометить своё „важное“» или
«поднять потолок» — оба обходят гейт.

**Лечение (ротация).** Одна строка индекса разрослась на 2,7 КБ — в ней был
**отчёт**, а не указатель. Ротация: деталь из индекса переезжает **в тело той
же записи** (тело — это уже существующий файл записи), а в индексе остаётся
короткий указатель на симптом. Запись не удалена, тег старения сохранён, гейт
зелёный, индекс похудел на 3,7 КБ.

**Правило, которое из этого следует.** Строка индекса — это **указатель**, а не
отчёт. Как только в строке появляется отчёт, она перестаёт быть индексом.
Это общий класс: «указатель сросся с содержимым» ломает и гейт, и чтение.

## 3. Роль в совете ≠ отдельный агент

**Наблюдение.** Промт требует совет экспертов с девятью ролями. Буквальное
прочтение — девять сессий/агентов — дорого и упирается в лимит аккаунтов
движка. Сделали так: **роль — это переключение внутри сессии**, но
**переключение обязано быть видно в разборе** (строка разбора начинается с
метки роли). Иначе совет вырождается в монолог: один человек рассуждает за
всех и не слышит возражений.

**Плюс — потолок на совет.** Записали: максимум 3 эксперта за раз, простая
задача идёт вообще без совета («координатор → программист»), шут — только по
решению координатора и только для крупного/спорного, и **шут не решает**: его
идеи попадают в совет как предложения. Без потолка число советников растёт
само, и совет дороже задачи.

**Что не делали:** не заводили настоящих агентов на роли (инфраструктура
ролей — отдельное решение), не создавали второе хранилище опыта (опыт идёт в
уже принятые места проекта), не заводили вторую копию карты архитектуры
(указатели на существующие карты вместо дублирования).
