# Троттлинг upload-сервера ВК приходит тремя лицами — и пауза лечит все три

Письмо от 19.06 и уточнение от 09.11 говорили: «upload-сервер отдаёт HTTP 405,
это антиспум, отход после паузы ~70 с». Живая проба 10.11 показала, что **405 —
лишь одно из трёх лиц одного и того же троттлинга**, и переповторять только
его — значит молча терять часть фото.

## 1. Три ответа ВК, которые лечатся одной паузой

| # | Ответ | Вид в журнале (если смотреть только тело) |
|---|---|---|
| 1 | HTTP **405**, тело — HTML от nginx | «не JSON» / пусто |
| 2 | HTTP **5xx**, тело — HTML «The page is temporarily unavailable» | «не JSON» / пусто |
| 3 | HTTP **200** + `{"server": N, "photo": "", "hash": "H"}` — файл залит, **фото не создано** | «пусто» |

Третье лицо — самое коварное: ответ выглядит как успех (200, есть `hash`), но
фото не создано. Код, считающий «фото есть, если `photo` непустой», на нём
тихо теряет снимок.

**Пауза 70 с + повтор лечит все три** — замерено 10.11: 5 из 5 отказов после
паузы вернули полноценное фото. Паузы 20 с **не хватает**: окно открывается
примерно через минуту (20 с → 405, 40 с → 405, 60 с → успех).

**Что отказом не является** (проверено пробой, чтобы не чинить не то): не дедуп
(одна картинка принята трижды подряд), не картинка (боевой конвейер 6/6), не
группа (14 боевых групп подряд — 13 успехов), не токен (весь замер — на
токене владельца, том же, что в бою).

**Практическое правило:** троттлинг — это **любой** из трёх ответов; лечится
все один и тот же способ (пауза + повтор). Отличать их для починки не нужно,
отличать для чтения журнала нужно: иначе все три выглядят как «вернул пусто»,
и по журналу нельзя понять, от чего отличаться.

## 2. Отдельно: пауза должна быть общей, а не персональной

Если сервер закрыл окно, следующая загрузка упрётся в то же окно. Пауза внутри
каждой загрузки значит «по паузе на каждое фото»; общая пауза на процесс
значит «одна пауза на эпизод троттлинга». Разница при ~70 отказах за вечер —
час ожидания против десяти минут.

## 3. Правило шире ВК: результат читается по предмету, а не по журналу попыток

Из той же ночи, и это, возможно, самое дорогое из трёх:

- По журналу воркера мы решили, что фото «не прикрепились нигде» — 72 отказа
  из 100 попыток выглядят как катастрофа.
- Перечитывание **самих постов** показало: **57 из 57 сборников вышли с
  фото** (258 фото, от 1 до 10, среднее 4,5), потеряна была **часть** фото
  (≈22 %), а не все.

Журнал показывает **попытки**, а не результат. Вывод «ничего не вышло»,
сделанный по журналу, был бы неверен — и в нашем случае был сделан. Правило
для любого проекта с внешним API: **после сбоя читай предмет (пост, файл,
запись), а не журнал попыток**.

Кандидат в GOTCHAS: уточнение инстанса от 19.06 (не новая запись) + отдельная
запись на «результат читается по предмету».
