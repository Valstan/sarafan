# MAX Bot API: что стоит знать до того, как строить канал в мессенджере

Мы начали работать с мессенджером MAX (канал уведомлений о рекламных заявках,
пилот #386). Собрал факты о **официальном** Bot API и один вывод, который
переносится на любой проект, который захочет говорить с MAX.

## 1. Факты об API (проверены по схеме `max-messenger-bot/max-bot-api-schemas`)

- **База:** `https://platform-api2.max.ru` (старый `platform-api.max.ru` платформа
  не рекомендует). Токен — **заголовком** `Authorization: <access_token>`;
  query-параметры больше не поддерживаются. Токен в URL — утечка в лог (тот же
  урок G239, что мы уже сделали для Telegram-релея).
- **Клавиатура приходит вложением**, а не отдельным полем:
  `{"type": "inline_keyboard", "payload": {"buttons": [[...]]}}`. Типы кнопок:
  `callback`, `link`, `request_contact`, `request_geo_location`, `chat`.
- **Ответ на нажатие:** `POST /answers?callback_id=<id>`, тело — `{"message":
  {"text": ...}}` (обёрнуто в `message`, плоский объект платформа тихо
  проигнорирует).
- **Подписка на события:** `POST /subscriptions` с `url`, `update_types`,
  `secret`. MAX подписывает запрос заголовком `X-Max-Bot-Api-Secret`.
- **Жёсткое время ответа:** вебхук должен ответить 200 за 30 секунд, иначе
  платформа делает три попытки (60 с, 150 с, 375 с) и **отключает подписку**.
  То есть любая ошибка внутри обработчика обязана превращаться в 200 — иначе
  один битый кейс тихо убьёт канал.
- **Лимит:** не больше двух сообщений в секунду в один диалог.
- **Админка чата/канала** даёт боту права `read_all_messages` и `write`; без
  них бот не получит вебхук и не сможет отвечать. Добавление бота в групповые
  чаты **по умолчанию запрещено** — включается в настройках бота.

## 2. Вывод, который переносится: личного аккаунта в MAX официально НЕТ

Официальный API — только для ботов. «Писать от своего имени» возможно
**только через неофициальный внутренний API** (есть сторонние обёртки, они
прямо предупреждают о риске блокировки аккаунта и о нарушении условий
сервиса). Мы это не используем.

Отсюда практический вывод для проектов: **«уведомления боту + ответ от
имени человека» в MAX невозможно**. Что возможно:

- бот пишет в чат/канал **от имени сообщества** (наш канал — сообщество ВК);
- «а напиши от личного аккаунта» — это ручное действие человека, и API тут не
  помогает.

## 3. Смежное: у ВК у user-токена нет scope `messages`

Тот же тупик, но в ВК: сообщество не может написать пользователю первым
(ошибка 901), а личный токен не умеет писать в личку вовсе. Поэтому «сначала
от имени сообщества, иначе от моего имени» на практике означает: сначала
сообществом (если автор разрешил), иначе — открыть личный диалог и дописать
руками. Обещать рекламодателю отправку от личного имени через API нельзя.

## 4. Отдельно: классификатор ленты — не тот инструмент для заявок

Наш детект рекламы в предложке был алгоритмическим (регулярки на контакты и
слова «разместить/прайс») и стал ошибаться в середине: «хочу разместить
рекламу» без контакта — уже заявка, «пишите по телефону» без коммерческого
намерения — ещё нет. Мы позвали нейросеть — но **с отдельным промптом**, а не
существующим классификатором сводки. Причина: классификатор отвечает на
другой вопрос («постить в сводку или нет»), и заявка рекламодателя получила бы
«удали» — ровно как и спам.

**Паттерн:** вопрос «это рекламная заявка?» и вопрос «это в ленту?» — разные
вопросы, и модель должна отвечать на каждый своим промптом.
