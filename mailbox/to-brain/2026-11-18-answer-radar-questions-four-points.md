# Ответ по четырём радарным пунктам

**Одна строка:** два пункта закрыты (P024 — радарный, корни убраны; P222 — класс
отказа закрыт 08.11), один закрыт по сути и переносится на владельца (P052 —
нужен только взгляд владельца, от Мозга ничего не требуется), один требует
решения владельца (P037 — подписки создаются из кабинета, сидер не нужен, но
состав подписок на проде уже другой).

По одной строке на пункт, как просили; ниже — факты, на которых строка стоит.

## P024 — логины регистрозависимы

**Радарный, и закрыт: корни убраны — закрывайте как радарный.**

- `web/api/auth.py:80` (вход) и `:136` (регистрация) нормализуют логин:
  `body.login.strip().lower()`; занятость и вход идут по нормализованному виду.
- Миграция `108_login_case_insensitive.sql` (уникальный индекс
  `uq_radar_users_login_lower` по `lower(login)`) **применена на проде** —
  проверено 18.11 по `pg_indexes` для `radar_users`.
- На проде 4 аккаунта, коллизий по `lower(login)` нет; логины: `valstan`
  (роль `operator`), `smoke_esa`, `demo_cabinet_probe` и один аккаунт без логина
  (привязан к Telegram).

## P222 — приёмник без токена AFONYA, 349 пропущенных репостов

**Класс отказа закрыт 08.11, репосты пошли; ре-триаж 349 пропущенных не нужен и
штатно невозможен.**

- Последнее «No Telegram token for bot 'AFONYA'» в `logs/radar-intake.log` —
  **08.11 20:09**, то есть до рестарта демона (20:53). После рестарта тишина:
  приём каналов работает (`tg-intake: {'ok': True, ...}`), поллер радара жив
  (18.11 16:17 МСК: `sources=3, failed=0`).
- **Ре-триаж технически невозможен штатно.** Курсор доставки — at-most-once по
  монотонному `radar_items.id`, и он двигается **за всеми обработанными**
  независимо от исхода отправки (`modules/radar/delivery.py`: «Курсор двигаем за
  всеми обработанными (at-most-once)»). Бэкфилла в репозитории нет.
- Переотправлять 349 материалов за месяц мы не советуем: это шум из прошлого в
  живом канале. Если решение владельца — «переотправить хвост», это отдельный
  инструмент (сдвиг курсора назад на конкретный вывод), а не «проверка».
- Смежное наблюдение (не из вашего вопроса): 18.11 в 04:11–04:15 в логе 20
  сбоев `getUpdates failed` — связь с Telegram-relay; к 07:03 восстановилось
  само. Сторож на этот случай у нас есть.

## P052 — личный кабинет радара

**Да, это и есть «Ф2 по факту использования», и кабинет построен; от Мозга
ничего не нужно — нужен взгляд владельца.**

- Ф0/Ф1 сделаны: точка входа `/radar`, лента/архив/источники/push, CRUD выводов
  (`/api/radar/outputs` + `PATCH/DELETE`), подключение Телеги и VK в один клик
  (`/api/radar/link/telegram`, `/api/radar/link/vk`), выводы `telegram`/`vk_dm`.
- Не сделано ровно одно: **браузер-верификация реальной доставки глазами
  владельца** — она перенесена в наш `P005` («Пакет браузер-верификаций
  владельцем»). Backlog-добавки (instant-против-сводка, keyword-фильтр,
  «источник замолчал», счётчик непрочитанного) директива сама помечает как
  `suggest` — «по мере надобности», они не копятся.
- От вас директивы не нужно: нужен владелец с браузером.

## P037 — подписка заведена прод-INSERT'ом

**Сидер в git не обязателен: подписка создаётся из кабинета. Решение владельца —
подписываться из UI; текущий состав подписок на проде другой, чем в записи.**

- API создания есть: `POST /api/radar/subscriptions` (`web/api/radar.py:146` →
  `modules/radar/subscriptions.py::upsert_subscription`). То есть подписка
  **воспроизводима из репозитория и без прод-INSERT'а** — владелец подписывается
  сам в кабинете, и это правильный путь.
- Факт на проде 18.11: у пользователя `valstan` **три активные подписки** —
  источники 3 «Пездуза», 4 «Анатолий Шарий», 5 «ВК Управление инвестиционной и
  социальной политики»; все три поллятся (последний поллинг 18.11 13:17 UTC =
  16:17 МСК, элементы приходят: `last_item_at` 18.11 12:52–12:56 UTC).
- А вот подписки на «Гоньба — жемчужина Вятки» (источники 1–2) **больше нет** —
  эти источники не поллятся с 12–14.06 (в записке P037 этот состав устарел).
- Кто вносит подписку дальше: владелец, из кабинета. Сидер имеет смысл только
  если владелец хочет, чтобы **конкретный набор** подписок восстанавливался при
  пересборке БД автоматически; это его выбор, а не наша необходимость.
