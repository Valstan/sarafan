# /sites — обслуживание сайтов кластера

Один вызов = один цикл питания сайтов: отбор → разбор глазами → сверка → доставка.
Источник — посты, вошедшие в опубликованные сводки `mi` (конфиг — [`config/content_conveyor.py`](../../config/content_conveyor.py), правила — [`rules/`](../../rules/)). DeepSeek лежит (P177) — вердикты выносит сессия глазами, штатным скриптом [`scripts/conveyor_manual_deliver.py`](../../scripts/conveyor_manual_deliver.py) (режимы `--emit` → `--check` → `--deliver`, окно по умолчанию 30 суток).

Сайты: `vmalmyzhe` (портал, публикует сам — D-091), `kazanskaya` (только черновики),
`sabantuy` (только черновики), `kultura` (публикует сам с 04.10 — `KULTURA_PUBLISH_KEY`).
**Калинино и РЦКД — не сайты, а секции `kultura`** (`kalinino`, `rckd`): сайт СДК Калинино
схлопнут в раздел портала (301, D-074), отдельного сайта РЦКД нет (разведка P185).
Единый заказ парсинга и постинга для портала Культуры = один прогон `--site kultura`,
разделы назначаются вердиктом (`section`), не уверен в учреждении — вези без `section`.

## Шаг 0. Состояние (read-only, Doyle)

```bash
ssh sarafan "sudo -n grep -E '^(CONVEYOR_SITES|CONVEYOR_DISABLED)=' /etc/setka/setka.env"
```

SQL — только файлом через stdin (PowerShell 5.1 ломает `||` и кавычки в строке,
см. G190/G235 у мозга — не доэкранируй, пиши файл):

```sql
select site || '/' || status || '=' || count(*) from conveyor_deliveries group by site, status order by site, status;
select site || '/failed_with_verdict=' || count(*) from conveyor_deliveries where status = 'failed' and verdict is not null group by site;
select site || '/selected ' || lip from conveyor_deliveries where status = 'selected' order by site, lip;
```

Читать так: `failed` без вердикта ждут движка (`--retry-failed` их не берёт);
`failed` с вердиктом — кандидаты на `--retry-failed`; `selected` — известный квирк
(первый lip батча рапортует delivered, строка остаётся `selected`, чинится
одиночной досылкой — перед прогоном сверить).

## Шаг 1. Отбор (по одному вызову на сайт, команды однострочные)

Многострочные скрипты через `bash -s` НЕ работают: PowerShell отдаёт stdin с CRLF
(`$'{\r'`). Длинные команды — тоже по одной на вызов (теardown hang G455 убьёт
цепочку целиком, см. handoff 10.10). Шаблон (всё ASCII, без `$` и бэктиков):

```bash
ssh sarafan "sudo -n bash -c 'set -a; . /etc/setka/secrets-token.env; . /etc/setka/setka.env; set +a; cd /home/valstan/SETKA && venv/bin/python scripts/conveyor_manual_deliver.py --site <site> --emit /tmp/sites-<ДД>-<site>.json'"
```

Успех — по маркеру `кандидатов=N`, не по exit-коду (teardown висит всегда).
`N=0` (Казанская/Сабантуй — норма: узкие ключевые слова) — дальше по этому сайту не идём.
Файлы вниз: `scp` по одному файлу за вызов (несколько источников в одном `scp` на
Windows-клиенте разваливаются). Проверить размер после каждого.

## Шаг 2. Разбор глазами

Читать emit-дайджест + [`rules/_base.md`](../../rules/_base.md) + `rules/<site>.md`.
Формат вердикта: `accept` → `section` (slug; неизвестный — не отказ, приёмник
примет с warning) + `title` (до 90 символов, без эмодзи и кликбейта) + `text`;
`reject` → `reason`. Сомневаешься — вердикта нет (пост остаётся в отборе),
а не hold: `parse_verdict` знает только accept/reject.

**Текст — байт-в-байт из снапшота emit** (гейт `manual_text_inflated`, урок 03.10):
карта `lip → {action, section, title}` пишется отдельно, тексты подставляет скрипт
сборки, руками не перепечатывать. Сверка 1:1 (кандидаты = карта) — до заливки.

## Шаг 3. Заливка, сверка, доставка (строго последовательно)

Файл вердиктов на прод — по одному `scp` за вызов. Затем на каждый сайт по очереди:

```bash
... --site <site> --check /tmp/<файл>     # зелено («доставка готова») обязательно
... --site <site> --deliver /tmp/<файл>   # только после зелёного check
```

`--deliver` без зелёного `--check` запрещён. Параллельные POSTы тяжёлых пачек роняют
чтение ответов — сайты строго по одному. В выводе deliver смотреть блок
`РАСХОЖДЕНИЕ С ЖУРНАЛОМ` (код 2): есть — дослать одиночкой, нет — журнал сошёлся.

## Что нельзя

- Портал и Культура уходят **в паблик** (`publish: true` — ключи на руках). Доставка
  туда — прод-операция с внешними эффектами: только по явному заказу владельца
  в том же ходе (гейт #025), черновики — тоже только заказом, не «по остаточному».
- Не чинить сайты разбором: заметил системное (чужой контент в потоке, битый slug) —
  в отчёт, правится отдельным PR/письмом.
- Дублей нет по построению: журнал `conveyor_deliveries` keyed by `(site, lip)`,
  повтор берёт только новое. Идемпотентность приёмника (`vkPostId`) — второй рубеж.
- `submit` классификатора и доставка конвейера — разные журналы: вердикт «publish»
  в `/progon` не означает доставку на сайт (туда — только этот скилл).
