# /progon — разбор очереди классификатора вместо DeepSeek

Пока DeepSeek отвечает 402 ([P177](../../docs/pending/P177-deepseek-402-i-oblachnaya-rutina.md)),
очередь разбирают сессии владельца. Один вызов = один ПРОГОН:
забор → разбор по постулатам → вопросы → отправка → журнал → отчёт.
Отметка «ПРОГОН» в Telegram уходит сама (фоновая задача на endpoint,
[`pilot_run`](../../modules/classifier/pilot_run.py)) — в промпт её
дописывать не надо.

**Вызов:** пользователь пишет `/progon` (или «прогон», «делай ПРОГОН»).
Можно перечислить районы явно (`/progon mi ur klz`) — иначе берётся
дефолтный набор из Шага 1. Агент без slash-команд открывает этот файл и
выполняет шаги. Памятка vendor-neutral ([ADR-0011](../../../brain_matrica/adr/0011-vendor-neutral-agent-contract.md)):
`AskUserQuestion` ниже — «задай вопрос обычным сообщением и дождись явного
ответа». Где у харнесса есть инструмент вопросов с кнопками — использовать
его: оператор решает один кликом.

## Шаг 0. Проверки

- `CLASSIFIER_INGEST_KEY` задан в env (проверить длиной, не значением).
  Не задан — остановиться и сказать владельцу, дальше не идти.
- Каталог прогона: следующий свободный `pilot_run<N>` в approved temp
  (`C:\Users\valstan\AppData\Local\Temp\opencode\`). **В репо — ничего**,
  кроме журнала (Шаг 5).

## Шаг 1. Забор

Набор по умолчанию (расширен 06.10 с трёх до восьми: замер очередей показал,
что mi/ur/klz — самые чистые именно потому, что их разбирают, а везде
остальном 40–50+; берём следующую пятёрку Кировской области с умеренными
очередями, больше за раз вручную не тянем):

```powershell
.\venv\Scripts\python.exe scripts/classifier_routine.py fetch --region mi --region ur --region klz --region podosinovets --region bogorodskoe --region nagorsk --region nema --region falenki --limit 15 --out C:\Users\valstan\AppData\Local\Temp\opencode\pilot_run<N> --no-media
```

**Правило объёма:** больше 3 регионов — лимит 15 на район (потолок ~120
постов за прогон). Три региона и меньше — лимит 30. Внимательный разбор
двух тысяч постов за раз невозможен: количество, превышающее ~120,
режется лимитом, а не качеством.

## Режим марафона (проба: покрыть все районы пачками)

всё не переварит — поэтому пачки по ~17 районов, **каждая в свежей сессии**
(контекст не таскает прошлые разборы). Вызов: `/progon batch1` … `/progon
batch4`. Лимит в марафоне — 10 на район. Вопросов — те же max 7 на сессию.

`count=0` по всем — доложить «очередь пуста» и завершить (Telegram
промолчит сам: `recorded=0` не отмечается).

## Шаг 2. Разбор

Прочитать `pending.json` + `postulates.md` из каталога. **Постулаты — закон:**
спор между publish и delete решает правило, а не сомнение.

- По каждому посту **с текстом** — ровно один вердикт: `theme` строго из
  канонического словаря (новости, администрация, объявления, культура, спорт,
  дети и образование, кругозор, соседи, мусор); `action` publish|delete|hold;
  `merge_with` — lip однособытийных постов **того же региона**;
  `urgent: true` только для отключений, аварий, МЧС, розыска;
  `importance` 0–100; `reasoning` одной фразой; `region_code` из поста.
- **`hold` — только по правилу 16 постулатов:** (а) география неоднозначна,
  свой район или чужой; (б) нет текста, а вложения нечитаемы. Иначе publish
  или delete обязателен — «сомневаюсь» не основание для hold.
- Посты без текста — без вердикта, перечислить в отчёте.
- `lip` копировать дословно.

## Шаг 3. Вопросы оператору (самообучение, часть 1)

Собрать сомнительные: `confidence < 65` или новый паттерн, под который нет
правила. **Не больше 7 за прогон** — усталость оператора дороже полноты;
остальное решить по правилу самому с честным confidence.

По каждому — вопрос с вариантами (publish/delete + тема + одна строка,
почему спорно; текст поста — не больше 500 символов). **Дождаться ответа
на все вопросы до отправки.** Ответы применяются как вердикты с
`confidence: 95` — это решение оператора, а не догадка.

## Шаг 4. Отправка

Собрать `verdicts.json` в каталоге прогона. Перед отправкой сверить 1:1:
число вердиктов = числу постов с текстом, ни одного дубля `lip`, ни одного
лишнего, `region_code` каждого совпадает с `pending.json`.

```powershell
.\venv\Scripts\python.exe scripts/classifier_routine.py submit <каталог>\verdicts.json
```

- `skipped_existing` = числу вердиктов — всё уже записано (первый POST мог
  уйти в таймаут чтения, это не ошибка, живых случаев два: 05.10 и 06.10).
- `skipped_invalid` > 0 — показать какие именно, починить и повторить.

## Шаг 5. Журнал решений (самообучение, часть 2)

Ответы оператора дописать в [`docs/ops/pilot-qa-log.md`](../../docs/ops/pilot-qa-log.md):
дата, lip, регион, выжимка поста (≤200 символов), вопрос, ответ,
применённый вердикт. Если ответов не было — не писать ничего, пустые строки
не нужны.

Это **сырьё для `/distill`** наряду с правками панели `/classifier`, а не
второй свод правил: мозг у системы один (эффективные постулаты), их читают
и DeepSeek, и сессии пилота. Когда DeepSeek вернётся, накопленные правила
достанутся ему сами — отдавать ничего никуда не надо.
Коммит журнала — обычным flow (`/close_session` подхватит), отдельного PR
на прогон не надо.

## Шаг 6. Отчёт

По регионам: получено / publish / delete / hold; пропущенные без текста;
вердикты с `confidence < 65` — списком с причиной. Отдельно подсветить
места, где оператор выбрал **против правила**: это кандидаты на правку
правила через `/distill`, а не молчаливое исключение.

## Как скилл учится (замкнутый контур, нового кода не надо)

1. Вопросы → ответы → журнал (этот скилл, Шаги 3 и 5).
2. Правки оператора в `/classifier` → `corrections`.
3. `/distill` чеканит правила → `postulates` (утверждает оператор в панели).
4. Следующий `/progon` забирает свежие постулаты (Шаг 1 тянет их всегда) →
   новые правила применяются автоматически.

Раз в ~10 прогонов или при накоплении ≥10 ответов в журнале — предложить
владельцу `/distill`. Порог осмысленности — как в самом `/distill`.

## Что нельзя

- Ключ — только из env, никогда в чат, файл, лог, команду.
- Файлы прогона — только temp-каталог (кроме журнала решений).
- Темы вне словаря — нет; `hold` вне правила 16 — нет.
- `submit` — один на прогон; повтор — только если первый ответ потерян
  (проверить `skipped_existing`).
- Не чинить чужие районы и чужой код по дороге: заметил системную находку
  (как утечка Малмыж-ИНФО в поток Кильмези 06.10) — записать в отчёт,
  правится отдельным PR, не разбором.
